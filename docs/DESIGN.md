# MoonDigest 设计规范

这里记的是界面和交互上已经定下来的规则。改界面前先读一遍。如果代码和这里写的不一致，先改代码；要是规则本身该变，就在同一个 PR 里一起改这份文件。颜色和尺寸的具体数值看 `extension/tokens.css`，这里只写每个值代表什么。

B站 页面上的颜色是 `tokens.css` 的第三份拷贝：`content.css` 里的 `--boc-*`（`content-tokens.selftest.js` 会核对）和 `badges.css` 里直接写的色值（也由 `content-tokens.selftest.js` 核对，新写死的色值要加进它的 `BADGE_TOKENS` 表）。改 token 时，在同一个 PR 里把这两处一起改。

## 1. 颜色：一种颜色只表示一件事

| 颜色 | token | 用在哪 |
|---|---|---|
| 粉 | `--accent` | 你现在在哪：当前页签、当前筛选、侧栏的当前项（左边一道粉线，字仍是 `--text`）、正在播放的那张卡片 |
| 蓝（实心） | `--action` | 下一步该做什么。每个页面只能有一个实心蓝按钮 |
| 蓝框 + 蓝底 | `--action` | 已选中的卡片（卡片上没有勾） |
| 蓝字 | `--link` | 只用于跳转链接，按钮不用蓝字 |
| 绿 | `--ok` | 保留、值得留 |
| 红 | `--danger` | 删除、取消收藏，以及必须你去处理的错误（没登录、AI 没配置、写入失败） |
| 琥珀 | `--warn` | 等待中、待确认、不挡你操作的提醒（倒计时、没拉全、还没写判断标准的小点） |
| 灰 | 其余 | 其他所有东西，包括正在运行的进度胶囊，以及 B站 封面上的「✓ 看完了」 |
| 紫 | 只在 `badges.css` | MoonDigest 在 B站 页面上加的东西：每组标记前的 2px 紫线、视频页那一行和「MoonDigest」字样、「+ UP 标签」悬停时的边框。B站 和 BewlyCat 自己的标签从来没有它 |

B站 页面上的 AI 判断照上表：值得留绿、可清理红、拿不准琥珀，浅色底是 AI 的建议；「已保留」「已取消收藏」是你自己做的决定，同色实底白字。

标签的色板要避开上面这几种颜色。粉和实心蓝在白底上做文字对比度不够，所以它们只用来画下划线、圆点、边框和填充；文字一律用 `--link` 或 `--text*`。卡片、视频投稿卡片和播放器那一行上的标签都是同一种小胶囊：标签色只画边框和底色，字用 `--text`。

## 2. 控件：按它是做什么的来选

| 控件 | 什么时候用 | 长什么样 |
|---|---|---|
| 胶囊（筛选片） | 筛选状态：点了只改列表里显示什么，不改数据 | 单选那一行（第 3 行）：26px 高、`--radius-pill`、没有底色也没有边框（悬停才出灰底），选中后变成 `--text` 实底。标签多选那一行：22px 高、用标签颜色描边 |
| 按钮 | 动作：改数据、改选中、打开弹窗或菜单、调用 AI | 32px 高、`--radius-sm`、1px `--border-strong` 边框、`--surface` 底。`.primary` 是那唯一的实心蓝，`.danger` 用于删除。`.quiet` 没有边框、灰色字，只用于「清空选中」和卡片上的次要按钮（「+ 标签」「✎ 备注」）。选中栏里的动作是普通按钮，其中可以有一个 `.primary`。分拣台头部的按钮（`.act-btn`：刷新、导出、全选、判断标准、标签管理、✦ AI 打标签）是例外：28px 高、没有边框、灰色图标和字，悬停出灰底；第 3 行跟着步骤的动作按钮也是 28px，照常有框 |
| 勾选框 | 选中状态 | 蓝色 ✓。「全选」是三态勾选：空框表示一个都没选，横杠表示选了一部分，蓝勾表示全选了。卡片上没有勾选框，选中看蓝框和蓝底 |
| 文字链接 | 只用来跳转：去 B站、去设置页 | `--link` 蓝字，悬停时出下划线，跳出站外的加 ↗ |

- 一个按钮开一个弹窗，弹窗标题和按钮同名，不在弹窗里放切换。「标签管理」只管标签，「✦ AI 打标签」只管 AI 打标签；要从一个去另一个，用文字链接。
- ✦ 放在会走到 AI 请求的入口上：「✦ AI 打标签」「✦ 问 AI」「✦ 继续问」、侧边栏的「✦ AI 总结」。纯管理用的弹窗不加 ✦，比如「标签管理」。
- 按钮点了没用时就灰掉，并且要说明原因：写在同一行，或者写进 tooltip 和 `aria-description`。不要做成能点、点了却弹「没有东西」。例外：没配 AI 时的运行按钮、没登录或断网时的刷新照样能点，因为点了会弹出带「去设置 / 去登录」按钮的横幅，比灰掉更有用。
- 数字输入框超出范围时自动改回范围内（离开输入框或点保存时，四舍五入到整数），不让浏览器拦着不存。留空表示用默认值；「0 = 自动」的框用 `data-zero-ok`，0 和负数变 0。两个设置弹窗都走 `TriageUi.clampNumbers`。
- 说明文字不要散在外面。改成按钮后面加一个琥珀色小点，点开以后说明写在里面，通常放进输入框的 placeholder。
- 收藏夹和关注的 UP 主卡片：点卡片任何地方（包括封面、头像、UP 名）都是选中或取消这一张；点视频标题在分拣台里播放（收藏夹卡片的标题、UP 主卡片里的投稿标题）。Shift 点选中从上一次点的那张到这张的一段；卡片里的按钮、输入框、标签片、「+ 标签」各管各的；拖选文字不选中。封面、标题、UP 名仍是去 B站 的真链接：右键、⌘/Ctrl 点、中键照常在 B站 打开。选中的卡片是蓝框加蓝底，卡片上没有勾选框；正在播放的卡片是粉框。X 键选中当前卡片。判断在 `TriageUi.cardPickClick` 和 `pickCard`，两种模式共用。
- 「视频投稿」的卡片和待播列表没有多选：点卡片任何地方都在分拣台里播放（「视频投稿」走 `TriageUi.cardPlayClick`），卡片里的按钮、输入框、标签片、UP 主链接各管各的，拖选文字不播放。键盘用标题链接回车播放，卡片本身不另加 Tab 停靠点。

## 3. 分拣台布局：两种模式用同一套行

第 3 行放状态：系统算出来的东西。第 4 行只放你自己打的标签。侧栏只管范围。

```
第 1 行  标题 · 数量  在 B站打开↗  今天 HH:MM 刷新过                   排序 ▾ ≡
第 2 行  步骤页签 / [UP 主 | 视频投稿]              [搜索…] [↻ 刷新] [⇩ 导出]
第 3 行  状态  状态片（见下）                [☐ 全选 N 个] [✎ 判断标准] [主按钮]
第 4 行  标签  自定义标签 …                          [标签管理] [✦ AI 打标签]
侧栏底部 ⚙ 收藏夹设置 / 关注设置

收藏夹
第 3 行  状态  全部 | 值得留 可清理 拿不准 已保留 | 看完了 | 已失效 | ✦ AI 刚打的 ×
侧栏     收藏夹列表

关注 · UP 主
第 3 行  状态  全部 | 活跃 慢更 断更 待查 没投过稿 未查 | 未打标签 已打标签 | ✦ AI 刚打的 ×
侧栏     全部 · 默认分组 · ★ 特别关注 · 自己建的分组… · [分组管理] · 已取消关注

关注 · 视频投稿
第 3 行  状态  全部 | UP 未打标签 UP 已打标签
```

- 第 3、4 行开头是行名「状态」「标签」：浅灰小字（12px、`--faint`），不是胶囊也不是按钮，宽度固定，所以两行第一个胶囊上下对齐，换行的胶囊也缩进对齐。760 及以下照样和第一个胶囊在同一行。
- 四行合成一张白卡（`--surface` 底、`--border` 描边、`--radius-lg` 圆角），卡片放在灰色页面底上，上面留 14px（600 及以下 8px）。卡里左右各留 16px。第 1 行一行写完：封面（原比例 16:10，40px 高）、名字 · 数量、在 B站打开、读取时间。第 2 行 40px 高，页签 13px，数量用等宽字；搜索框和按钮 28px 高。第 3、4 行上下各留 8px，列表上面也留 8px，第 2 行和第 3 行下面各有一道 `--border` 细线（1024 及以下第 2 行是两行，细线画在第 3 行上面）。卡里不再加色带或框。
- 收藏夹的第 3 行没有「未打标签 / 已打标签」，关注有（原因见 §8）。
- 第 3 行用细竖线分组。组内单选，再点一次已选中的就取消；组和组之间是「并且」。点「全部」只清空第 3 行，不碰第 4 行的标签和侧栏。
- 「未分析」没有 AI 判断，不画这一组（不是 0，是不可能有）。「已保留」放在 AI 判断组最后，只在「阅览全部」出现。
- 「待查」的全称「慢更或断更 · 待查」写在 tooltip 里。
- 只是有时才有的条件片（看完了、已失效、AI 刚打的）放在第 3 行最后，平时的布局不会因为它们出现或消失而挪动。「视频投稿」还没有观看进度，所以没有「看完了」。
- 「全选」放在第 3 行右边按钮组的最前面，条件片出现或消失时它不动。「视频投稿」没有全选。选中栏里不放全选。第 3 行没有「多选」开关：点卡片就是选中（§2）。
- 第 3 行和第 4 行右边的按钮要右对齐。有侧栏时（宽于 760），筛选片按组换行，一组放不下才在组内换行，右边按钮钉在第一行右上。没有侧栏时（760 及以下），筛选片占满整行，按钮另起一行靠右，正好在第 4 行按钮上方。
- 排序放在第 1 行右边。「视频投稿」只能按 B站 给的发布时间排，所以不显示排序。「已取消关注」时标题写「已取消关注 · N」。
- 搜索框放在第 2 行，两种模式各记各的搜索词。提示文字（和读屏用的 aria-label）要写出搜索范围，比如收藏夹的「在「想学的技能」 · 未分析里搜」、关注的「在「硬核科普」 · 活跃里搜」。开了搜索或任何筛选时，搜索框旁边显示「N 个结果」。
- 导出只有一个入口，就是第 2 行的「导出」菜单。
- 1024 宽时，第 2 行的搜索框和按钮换到页签下面一行。720 宽时没有侧栏：侧栏变成顶栏的下拉框（选项带数量），⚙ 放到第 2 行最后。
- 「✦ AI 打标签」在「视频投稿」和「已取消关注」里灰掉并写原因，不隐藏。
- 「所有收藏夹」里也能标题粗看、细看和「按新标准重新粗看 / 细看」。每个视频按它所在收藏夹的判断标准判断，在几个收藏夹里的按排在最前的那个（侧栏顺序）。第 3 行没有「判断标准」按钮；点这几个按钮先弹出和按钮同名的弹窗，列出这次涉及的每个收藏夹、视频数和它的判断标准（可改，存法和「判断标准」弹窗一样），按钮写「开始粗看 N 个」，取消什么都不做。粗看一批只发同一个收藏夹的视频。
- 「✦ AI 打标签」在「所有收藏夹」里按收藏夹分开打：每个收藏夹用自己的标签和新建名额，在几个收藏夹里的视频每个收藏夹都打；进度写「「想学的技能」第 2/3 批」。可用标签同名的合成一个片，点掉就是这个名字在每个收藏夹都不给 AI 用。新标签建在提出它的收藏夹，确认页在后面写「建在「X」」，两个收藏夹的同名新标签分开勾选。整次一个建议、一次应用、一步撤销。「标签管理」和选中栏的「标签…」仍只在具体收藏夹里。
- 关注会记住侧栏选的是哪一项。
- 头部随滚动收起：往下看（列表往下翻，超过整个头部的高度）就收成一条细栏，只剩「名字 · 数量」、第 2 行的页签和右边的搜索 / 刷新 / 导出，没有封面，细栏自己是一张圆角白卡，上面留的空和展开时一样；一往回滚（任何位置，不只是顶上）立刻整块回来，回到顶上一定是完整的。小于 8px 的滚动不算。焦点进到头部（Tab、按 / 搜索、关掉弹窗后焦点回到按钮）也整块回来。切换模式时从完整的开始。列表从头部底下穿过，收起和展开只是平移和淡出，卡片不跳；播放器的上沿跟着头部的下沿走。收起和展开用 0.15 秒，系统设了减少动态效果就不动画。760 及以下一样。选中栏和弹窗不管头部收没收，窗口矮也不特殊处理。
- 播放器（点卡片后在右边打开的 B站 页面）没有顶栏。从上往下是：收藏夹的「视频标签」行、「UP 标签」行，然后是 B站 页面。关闭是播放框右上角骑在边框上的圆形 ×（`#viewerCloseBtn`，一半在框外，tooltip「关闭播放（Esc）」），或者按 Esc。标签行右边留出空，× 不压住标签。760 及以下播放器占掉列表的位置，× 还在同一个角上。

## 4. 筛选和计数

- 第 3 行每组的数量不算本组自己的选择，但算别的组、第 4 行、搜索和侧栏。固定的组数量为 0 时变淡，不隐藏；侧栏也一样。条件片（看完了、已失效、AI 刚打的）数量为 0 时隐藏，开着的时候照样显示，方便关掉。「全部」的数量是清空第 3 行以后的。
- 标签行（第 4 行）：只列当前页签里有视频（或 UP 主）带着的标签，打开的标签照样显示。每个标签带数量：收藏夹数当前页签的视频，关注的「UP 主」数 UP 主，「视频投稿」数视频。多选是「并且」，数量不算第 4 行自己的选择。
- 「全选」「标题粗看这 N 个」里的 N 只算你现在看得见的，也就是经过搜索和筛选之后剩下的。被筛掉的视频不受影响，它们的选中状态也保留。选中只属于当前页签：换页签清空选中；保留、取消收藏或跑完一步后离开这个页签的视频，也离开选中。

## 5. 改 B站 的操作和撤销

- U 只撤销当前模式里的操作，不会撤到另一个模式。切换收藏夹只清掉收藏夹的步骤，关注的不受影响；删除标签会清掉这个模式里改标签的步骤。
- 单个操作不弹确认，提供按 U 撤销，比如取消收藏、特别关注、单个「重新关注」。撤销重新关注会在 B站再取消关注，「已取消关注」里的记录和标签照原样放回。
- 单个「取消关注」例外，要弹确认，因为重新关注后原来的关注时间就没了。
- 批量操作要弹确认。确认框标题以「在 B站」开头，按钮上写数量，比如「取消关注 12 个」。
- 「所有收藏夹」里也能批量保留和批量取消收藏（选中栏和第 3 行按 AI 判断的按钮，和具体收藏夹一样只算还没处理的）。保留本来就不分收藏夹，不弹窗。批量取消收藏的确认框标题照常以「在 B站」开头，列出这批视频所在的收藏夹和各有几个，都默认勾选，按钮写「取消收藏 N 个」，N 跟着勾选变；视频在勾选的每个收藏夹里都取消，一个收藏夹都不剩才离开列表。按收藏夹一个一个来，进度写「取消收藏中「X」 3/10」。整批一步，U 把每个视频重新收藏回取消掉的每个收藏夹。
- 只改扩展本地数据的操作（标签、备注、AI 建议）都能按 U 撤销。一次操作算一步，比如关一次打标签面板就是一步。
- 要撤销的这一步改了 2 个以上对象时，撤销前先确认，比如批量保留、批量取消收藏、批量移到或复制到分组（整批算一步）、AI 打标签、选中栏的「标签…」。
- 标签只存在扩展里，不改 B站。
- 关注的分组就是 B站 的关注分组，像收藏夹的收藏夹一样在这里管：侧栏列出默认分组、★ 特别关注和自己建的分组；选中栏有「移到分组…」「复制到分组…」，和收藏夹的移动 / 复制是同一个弹窗，里面可以新建分组；「分组管理」里新建、改名、删除。特别关注就是一个分组（B站 的 -10），卡片上的 ★ 只是把这一个 UP 主放进或移出它。默认分组和特别关注是 B站 固定的，不能改名或删除；默认分组只能移进去，不能复制进去。默认分组是「不在任何自己建的分组里」，特别关注只是多一个标记，所以从默认分组移到特别关注其实是加进去，人还在默认分组：弹窗和提示都写「加进」，不写「移到」。
  - 单个移动、复制、★ 和改名不确认，按 U 撤销（放回原来的分组、改回原名）。批量的弹窗本身就是确认，标题以「在 B站」开头，按钮上写数量；整批一步，撤销前先确认。
  - 删除分组一定确认，写明里面的 UP 主还关注着、不在别的分组的回到默认分组，删除后不能按 U 撤销；删除时清掉这个模式里改分组的撤销步骤。
  - B站 确认成功后才改本地的分组数据。超时报「不确定 B站 是否已改，刷新后看一下」，不改本地、不记撤销。

## 6. 用词

下面的用词表和时间格式管的是分拣台。

| 用 | 不用 |
|---|---|
| 刷新 | 更新、同步（按钮上） |
| 标签管理 | 管理标签 |
| ✦ AI 打标签 | 批量打、标签 |
| 在 B站打开 | 去 B站、打开原视频 |
| 收藏夹设置 / 关注设置 | 分拣设置、设置（单独出现时） |
| 导出 | 批量导出（作为入口名时） |
| 摘录或笔记…（导出菜单里那一项，按产出命名） | 批量导出… |
| 判断标准 | 标准、规则 |
| 待播（临时的待看清单，跨收藏夹，不参与导出；卡片上写「+ 待播」「✓ 待播」） | 播放列表、优先看 |

时长写成 `1:15:00` 或 `9:47`，不满一小时分钟不补 0。数量写成 `12.3万`、`2.5亿`。「刷新过」和「已出分拣范围」的离开时间写成「今天 HH:MM」「昨天 HH:MM」「10月5日 HH:MM」，往年写「2025年10月5日」。卡片上的时间（发布、最后投稿、关注于、取关于）写相对时间（「1 天前」），悬停显示具体日期。

## 7. 代码怎么共用

- 两种模式都画的东西，只在 `extension/triage/shared.js`（`TriageUi`）里写一份：标题行、排序、搜索框、筛选片、第 3/4 行的行名（`labeledRow`）、「AI 刚打的」片（`aiRecentChip`）、选中栏（`selbar`）、移动 / 复制弹窗（`askTransfer`：收藏夹传收藏夹，关注传分组）、侧栏项（`sideItem`）、刷新和导出按钮、进度胶囊、空状态和里面的刷新（`refreshEmpty`）、头部随滚动收起（`headroom`）、列表为空的原因（`noMatch`）、撤销前的确认（`undoAsk`）、设置行（`fillSetRows`，包括「AI 打标签每批数量」）、格式化函数、AI 建议的合并（标签名清洗和标签颜色在 `extension/tag-core.js`）。「收藏夹设置」和「关注设置」两个弹窗的结构都写在 `triage.html` 里。发现两边各写了一份，就合并进去。
- 打标签面板只有一个：`extension/triage/tag-picker.js`。例外：B站 页面上的「+」标签面板（`badges.js`）在封闭的 shadow DOM 里，暂时用不了 tag-picker.js，标签的纯函数（颜色、标签名清洗、新标签 id、下一个颜色）放在 `extension/tag-core.js`（`BocTagCore`）里，`badges.js`、`shared.js`、`follow.js` 和 `triage.js` 都用它，manifest 和 `triage.html` 都在它们之前加载。`tag-core.selftest.js` 会查别处有没有再写一份。面板本身以后再迁到 tag-picker.js。「标签管理」和「✦ AI 打标签」弹窗也各只有一个：`extension/triage/tag-dialogs.js`；关注的「分组管理」也用「标签管理」这个弹窗，adapter 换掉标题、文字和每行的样子。模式打开它们时只传一个 adapter，里面是单位（视频 / UP 主）、上限和数据，文字、布局和确认页的计数（改动数、按标签汇总、「用在 N 个」）都在弹窗里。
- 所有输入框和快捷键都要走 `extension/typing.js`（`BocTyping`）：
  - 回车和 Esc 的处理函数，开头先写 `if (BocTyping.composing(e)) return;`。
  - 全局快捷键，开头写 `if (composing(e) || typingIn(e)) return;`。
  - 实时过滤的输入框用 `bindLive`。列表的搜索框用 `TriageUi.bindSearch`：Esc 清空，空框再按 Esc 移出焦点。
  - 这样以后新加的输入框，用输入法打字也不会出问题。
- 键盘只有一个全局处理函数，在 `triage.js` 的 `onKey` 里。播放器里按的 T / Esc 也只有一个 message 监听，同在 `triage.js`。关注模式用 `MoonTriage.setModeKeys` 注册自己的按键，两处都先问它。
- 播放器的 × 不放在 `#viewer` 里，而是紧跟在它后面的同一个格子（grid-area `viewer`）里，因为 `#viewer` 要 `overflow: hidden` 裁出圆角；`#viewer[hidden]` 时 CSS 把它一起藏起来。
- B站 页面上画什么只在 `badges.js` 写一份：`surfaceOf` 认出是哪种页面（首页和搜索、收藏夹、稍后再看和历史、动态、UP 空间、视频页、分拣台播放器），`SURFACES` 写每种页面显示哪些东西，顶栏弹窗按元素认（`.bew-popover`、`.v-popover`）。标签放得下多少只有一个函数：`fitCount` 算个数，`fitBoxes` 量宽度、藏掉放不下的、写「+N」，`ResizeObserver` 在容器变宽变窄时重量。
- 播放器下的标签行只有一种写法：`TriageUi.viewerLine`，行名用第 3/4 行的 `labeledRow`。收藏夹的「视频标签」行在 `triage.js`，「UP 标签」行在 `follow.js`，收藏夹每次画完自己那行就通过 `MoonTriage.setViewerHook` 让关注重画 UP 那行。
- 后台（`background.js` 的 service worker）也加载 `tag-core.js` 和 `shared.js`，日期、时长、标签名清洗直接用 `TriageUi`，不在 `triage-bg.js` 里另写。加载顺序以 `background.js` 的 `importScripts` 为准，后台的 selftest 照它读。
- 「✦ AI 打标签」的后台只有一份：`triage-bg.js` 的 `triageAiCommand`（指令检查、新建上限 0–50、解析）。关注只把 UP 主整理成条目，带上自己的 unit 调它。
- B站 的 GET 只有一个通道：`triage-bg.js` 的 `triageBiliGetJson`，30 秒没回应算断网。收藏夹每次只试一次，限流由页面退避；关注传入自己的队列（间隔、断网重试、风控整队暂停）。写操作 `triageBiliPost` 也有这 30 秒超时，但只发一次、从不自动重试；超时报「不确定 B站 是否已改」，调用方按失败处理，不改计数、不记撤销。风控码统一用 `BILI_RISK_CODES`，WBI 签名用 `sites.js`。

## 8. 定下来的决定（改之前先问用户）

- 第 2 行是流程和视图，第 3 行是状态（系统算出来的判断），第 4 行是标签（你自己建的），侧栏只放范围。为什么：状态和标签不是一个层级，放在一行就分不清。
- 关注的「活跃 / 慢更 / 断更…」和收藏夹的「值得留 / 可清理 / 拿不准」是同一层，都是对这一条的判断；它们不对应「未分析 / 粗看 / 细看」，那是分拣进度。
- 收藏夹没有「未打标签 / 已打标签」，关注有。为什么：收藏夹的标签只是收藏夹里的细分，关注的标签是主要分类。
- 第 3、4 行开头有灰色大字「状态」「标签」，行与行之间有间距和细线。为什么：宽屏下一行两头离得太远，两行胶囊容易看混。
- 只是有时才有的条件片（看完了、已失效、AI 刚打的）放第 3 行最后，数量为 0 时隐藏；固定的组为 0 时变淡。为什么：平时的排版不跳动。
- 「全选」放在右边按钮组最前面，是三态勾选。为什么：条件片出现或消失时它不动。
- 多选不用开关：点卡片就是选中，点标题才是播放。为什么：分拣时选比看多，第一次选不用去找藏着的勾选框。卡片上不放勾选框：蓝框加蓝底已经够看出选中，圆勾在小封面上会压住 AI 判断标签和「看到 X%」标签（2026-10-09 去掉）。
- 「所有收藏夹」的 AI 判断按每个视频排在最前的收藏夹的判断标准，AI 打标签按收藏夹分开打。为什么：一次请求只带一份判断标准、一个收藏夹的标签；同一个视频在两个收藏夹里各有一套标签。
- 「待查」一直显示，0 时变淡。为什么：以前它一消失，后面的片就跟着挪位。
- 「标签管理」和「✦ AI 打标签」是两个弹窗、两个按钮，放在标签行右边；两种模式用同一份组件。为什么：一个按钮只做一件事；收藏夹的标签按收藏夹分，放侧栏会被当成全局的。
- 关注的第二个页签叫「视频投稿」，不叫「动态」。为什么：这里只拉视频，B站 的动态还有图文和转发，B站 自己也叫视频投稿。
- 「待播」（原来叫「优先看」，后来叫「播放列表」）是临时的待看清单，跨收藏夹，不参与导出（摘录、CSV、完整备份里都没有它），也没有「优先看过」的标记。
- 卡片上写「+ 待播 / ✓ 待播」，不写名词「播放列表」。为什么：名词看不出点了会怎样；不叫「稍后再看」，因为那是 B站 自己的功能，侧栏里也有同名收藏夹。
- 导出只有一个入口；排序在第 1 行右边；搜索框写出搜索范围。
- 关注的分组和收藏夹一样在这里管：新建、改名、删除、移到、复制到，特别关注当作一个分组（以前是只读，★ 是单独的开关）。为什么：关注的分组和收藏夹一样是 B站 上的容器；特别关注就是一个分组。
- U 只撤销当前模式的步骤。单个改 B站 的操作不确认，可以按 U 撤销；单个取消关注要确认，因为原来的关注时间回不来；单个重新关注不确认，可以按 U 撤销；一步改了 2 个以上对象时，撤销前先确认。
- 按钮灰掉要写原因。说明文字不摆在外面，用琥珀色小点，说明写在里面的占位文字里（判断标准、标签管理）。
- 「全部」后面有竖线，组和组之间也有竖线；组内单选，组和组同时生效。
- 卡片上的时间写相对时间，悬停显示日期；时长写 `9:47`、`1:15:00`。
- 播放器下的标签行前写明「视频标签」「UP 标签」，空的时候只留「+ 标签」。为什么：收藏夹的播放器下有两行标签，以前都只写「未打标签」，分不清哪行是视频的、哪行是 UP 主的。收藏夹两行都有（视频标签在上，UP 标签只在这个 UP 主是你关注或取关过的时候有，因为 UP 标签打在关注的 UP 主上）；关注只有「UP 标签」，因为视频投稿不在收藏夹里。T 只改它在的那一行（收藏夹改视频，关注改 UP），所以「T」只写在那一行的「+ 标签」上。
- 头部随滚动收起：往下看就收成一条细栏，一往回滚立刻整块回来；封面不缩，静态排版不变。为什么：屏幕高度留给卡片，同时随时能操作筛选。
- 侧栏目前留白：2026-10-09 看过「带进度 / 放待播」两个方案，决定先不动。
- 播放器没有顶栏：标题在 B站 页面里有，专注模式在半屏里不好用，在 B站打开靠右键卡片；关闭是播放框右上角骑在边框上的圆形 ×，不放在标签行末尾（会像关闭那一行）。
- 播放器的 UP 标签行只给关注数据里有的 UP：在关注的可以加标签；已取消关注的只显示原来的标签、没有「+ 标签」；从没关注过的整行不显示。为什么：UP 标签挂在关注列表的 UP 上，没关注的人没有地方挂；另存一份「打了标签但没关注的 UP」会多出一套看不见、不跟同步的数据。视频投稿同理反过来：那些视频不在收藏夹，只能给 UP 打标签，不能给视频打。
- 播放器里没有「已看，下一个」：待播从面板里移除或清空就行。
- 待播里每条是「移除」，不是「已看」。为什么：待播是临时的待看清单，没有「看过」这个状态。
- B站 页面上 MoonDigest 加的每一组东西前面都有一道 2px 紫线（§1 的紫）。为什么：要一眼分出哪些是 MoonDigest 加的、哪些是 B站 或 BewlyCat 自己的；一组什么都显示不了时连紫线也不画，不留空记号。
- 位置定归属：视频的东西（AI 判断、视频标签）只放在标题前或标题那一行，UP 标签只放在 UP 名字后面。两种标签样子也不同：视频标签是分拣台那种描边胶囊，UP 标签是前面一个色点（分拣台 UP 标签面板和动态筛选条的样子）。为什么：两种标签挨得近的地方（卡片）只靠位置不够快。
- 每种页面显示什么：视频页标题下那一行是 AI 判断、一句话和视频标签，UP 名字下面单独一行是 UP 标签和「+ UP 标签」；视频页右侧推荐和合集列表是 AI 判断、视频标签和 UP 标签，没有「+ UP 标签」；首页、搜索、稍后再看、历史是 AI 判断、视频标签、UP 标签，「+ UP 标签」悬停才出现；收藏夹页是 AI 判断和视频标签，不放 UP 标签；动态只有 UP 标签和筛选条，不放 AI 判断和视频标签，「+ UP 标签」悬停才出现；UP 空间是 AI 判断和视频标签，昵称后面是这个 UP 的标签，「+ UP 标签」一直显示。B站 和 BewlyCat 的页面一样。为什么：卡片小，只放分拣时用得上的；名字和标题旁边的地方本来就挤。按页面上视频的性质放：动态里都是新视频，没收藏过也没分拣过，有用的只有 UP 是谁。
- 标签按位置放得下多少放多少，放不下的写「+N」（不按个数截），悬停或聚焦「+N」列出全部。为什么：标签名长短不一，按个数截时长名字会被切掉半个，或者只剩一道空紫线。标题前的一组最多占标题宽度的 60%，不挤掉标题。
- UP 标签不能点，也不再跳去分拣台。能点的只有写着字的「+ UP 标签」，它打开标签面板；面板里有「在分拣台「关注」里打开这个 UP ↗」，点它打开「关注」并清掉筛选，这个 UP 的卡片停在列表中间。为什么：标签片放在 UP 名字的链接里，点它跳走和点名字去空间页分不清。
- 视频标记要单独占一行时放在标题上面，不放下面（收藏夹页一直这样）。为什么：放在标题下面会和下一个视频挨着，像是下一个视频的。
- 顶栏弹窗（收藏、历史、稍后再看）有 AI 判断、视频标签、UP 标签、封面进度条和观看进度标记，没有「+ UP 标签」；动态弹窗和动态页一样不放 AI 判断和视频标签；标签放不下时照样写「+N」，看过的封面写「看到 N%」不带 ✓，看完的写「✓ 看完了」。为什么：「+」打开的面板会在弹窗收起后没有着落；弹窗封面小，「✓ 看到 95%」会溢出。
- 分拣台的播放器（`html[data-mdg-viewer]`）里 `badges.js` 什么都不画、什么都不读。为什么：播放器上面的「视频标签」「UP 标签」两行已经有了。
- 设置里有三个开关：「在 B站页面显示 AI 判断」（默认关）、「在 B站页面显示视频标签」（默认开）、「在 B站页面显示 UP 标签」（默认开）。UP 标签关掉时 UP 标签、「+ UP 标签」和动态的筛选条都不画。为什么：AI 判断是分拣时看的，日常刷 B站 多数人不想看到；有人只想要其中一种标记。
- 两个开关下面是「B站页面上显示什么」表：一行一种页面，一列一种标记（AI 判断、视频标签、UP 标签、「+ UP 标签」、观看进度），格子是上面那张矩阵允许的，取消勾选就不在那里画；矩阵不放的格子写「–」，不能勾。动态页的「UP 标签」那格也管筛选条，行名上写明。开关关着、或「封面显示」是关时，对应的列变灰但保留勾选。存成 sync 里的 `biliMarksOff`（关掉的格子），矩阵只在 `extension/bili-surfaces.js` 写一份，`badges.js` 和设置页都读它。为什么：每种页面要什么因人而异，但矩阵之外的格子没有合适的位置，不让选。
- 封面上的「✓ 看完了」是深灰底白字，不用粉，B站 页面和分拣台一样。为什么：粉在 §1 是「你在哪」；看完了不是判断，归灰。进度条仍照 B站 自己的样子（粉条），因为它就是在模仿 B站 的进度条。
- B站 自己已经写了「已看完」的封面（稍后再看），不再加「✓ 看完了」。每种页面都画淡的「看到 N%」。历史的「遮罩」样式换成角标，稍后再看和 UP 空间照设置。为什么：历史里每个视频都看过，遮罩会盖住每张封面；稍后再看和 UP 空间里很多没看过，遮罩只盖看完的那些。
- 「已取消收藏」和「AI 可清理」同是红（§1），但「已取消收藏」是实底白字、AI 判断是浅色底。为什么：一个是你做了的决定，一个是 AI 的建议。
