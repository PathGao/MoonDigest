# MoonDigest 设计规范

这里记的是界面和交互上已经定下来的规则。改界面前先读一遍。如果代码和这里写的不一致，先改代码；要是规则本身该变，就在同一个 PR 里一起改这份文件。颜色和尺寸的具体数值看 `extension/tokens.css`，这里只写每个值代表什么。

B站 页面上的颜色是 `tokens.css` 的第三份拷贝：`content.css` 里的 `--boc-*`（`content-tokens.selftest.js` 会核对）和 `badges.css` 里直接写的色值（没人核对）。改 token 时，在同一个 PR 里把这两处一起改。

## 1. 颜色：一种颜色只表示一件事

| 颜色 | token | 用在哪 |
|---|---|---|
| 粉 | `--accent` | 你现在在哪：当前页签、当前筛选、正在播放的那张卡片 |
| 蓝（实心） | `--action` | 下一步该做什么。每个页面只能有一个实心蓝按钮 |
| 蓝框 + ✓ | `--action` | 已选中的卡片和勾选框 |
| 蓝字 | `--link` | 只用于跳转链接，按钮不用蓝字 |
| 绿 | `--ok` | 保留、值得留 |
| 红 | `--danger` | 删除、取消收藏，以及必须你去处理的错误（没登录、AI 没配置、写入失败） |
| 琥珀 | `--warn` | 等待中、待确认、不挡你操作的提醒（倒计时、没拉全、还没写判断标准的小点） |
| 灰 | 其余 | 其他所有东西 |

标签的色板要避开上面这几种颜色。粉和实心蓝在白底上做文字对比度不够，所以它们只用来画下划线、圆点、边框和填充；文字一律用 `--link` 或 `--text*`。

## 2. 控件：按它是做什么的来选

| 控件 | 什么时候用 | 长什么样 |
|---|---|---|
| 胶囊（筛选片） | 筛选状态：点了只改列表里显示什么，不改数据 | 单选那一行：26px 高、`--radius-pill`、灰底没有边框，选中后变成 `--text` 实底。标签多选那一行：22px 高、用标签颜色描边 |
| 按钮 | 动作：改数据、改选中、打开弹窗或菜单、调用 AI | 32px 高、`--radius-sm`、1px `--border-strong` 边框、`--surface` 底。`.primary` 是那唯一的实心蓝，`.danger` 用于删除。`.quiet` 没有边框、灰色字，只用于「清空选中」和卡片上的次要按钮（「+ 标签」「✎ 备注」）。选中栏里的动作是普通按钮，其中可以有一个 `.primary` |
| 勾选框 | 选中状态 | 蓝色 ✓。「全选」是三态勾选：空框表示一个都没选，横杠表示选了一部分，蓝勾表示全选了 |
| 文字链接 | 只用来跳转：去 B站、去设置页 | `--link` 蓝字，悬停时出下划线，跳出站外的加 ↗ |

- 一个按钮开一个弹窗，弹窗标题和按钮同名，不在弹窗里放切换。「标签管理」只管标签，「✦ AI 打标签」只管 AI 打标签；要从一个去另一个，用文字链接。
- ✦ 放在会走到 AI 请求的入口上：「✦ AI 打标签」「✦ 问 AI」「✦ 继续问」、侧边栏的「✦ AI 总结」。纯管理用的弹窗不加 ✦，比如「标签管理」。
- 按钮点了没用时就灰掉，并且要说明原因：写在同一行，或者写进 tooltip 和 `aria-description`。不要做成能点、点了却弹「没有东西」。例外：没配 AI 时的运行按钮、没登录或断网时的刷新照样能点，因为点了会弹出带「去设置 / 去登录」按钮的横幅，比灰掉更有用。
- 说明文字不要散在外面。改成按钮后面加一个琥珀色小点，点开以后说明写在里面，通常放进输入框的 placeholder。

## 3. 分拣台布局：两种模式用同一套行

现在的样子：

```
第 1 行  标题 · 数量  在 B站打开↗  今天 HH:MM 刷新过                   排序 ▾ ≡
第 2 行  步骤页签 / [UP 主 | 动态]                  [搜索…] [↻ 刷新] [⇩ 导出]
第 3 行  全部 | 值得留 可清理 拿不准  [☐ 全选 N 个]          [✎ 判断标准] [主按钮]
第 4 行  看完了  自定义标签 …                        [标签管理] [✦ AI 打标签]
侧栏底部 ⚙ 收藏夹设置 / 关注设置
```

- 排序放在第 1 行右边。「动态」只能按 B站 给的发布时间排，所以不显示排序。
- 搜索框放在第 2 行，两种模式各记各的搜索词。提示文字要写出搜索范围，比如「在「想学的技能」· 未分析里搜」。搜索框旁边显示「N 个结果」。
- 导出只有一个入口，就是第 2 行的「导出」菜单。
- 第 3 行和第 4 行右边的按钮要右对齐，720 宽时也一样。
- 1024 宽时，第 2 行的搜索框和按钮换到页签下面一行。720 宽时没有侧栏：下拉框放到顶栏，⚙ 放到第 2 行最后。
- 「全部」和后面的分类之间加一条细竖线，因为「全部」不是一种分类。
- 「全选」紧跟在筛选胶囊后面，选中栏里不再放全选。

### 新的行规则（设计中，还没实现）

第 3 行放状态：系统算出来的东西。第 4 行只放你自己打的标签。侧栏只管范围。

```
收藏夹
第 3 行  全部 | 值得留 可清理 拿不准 | 未打标签 已打标签 | 看完了 已失效 AI 刚打的
第 4 行  自定义标签 …                                [标签管理] [✦ AI 打标签]
侧栏     收藏夹列表

关注 · UP 主
第 3 行  全部 | 活跃 慢更 断更 … | 未打标签 已打标签 | AI 刚打的
第 4 行  自定义标签 …                                [标签管理] [✦ AI 打标签]
侧栏     全部 · ★ 特别关注 · B站 分组 · 已取消关注

关注 · 动态
第 3 行  全部 | UP 未打标签 UP 已打标签 | 看完了
第 4 行  自定义标签 …
```

- 第 3 行用细竖线分组。组内单选，组和组之间是「并且」。点「全部」清空第 3 行所有组。
- 只是有时才有的条件片（看完了、已失效、AI 刚打的）放在第 3 行最后，平时的布局不会因为它们出现或消失而挪动。
- 动态没有更新状态那一组。

## 4. 筛选和计数

- 单选筛选（第 3 行、关注的状态、侧栏）：数量为 0 时变淡，不隐藏。例外：关注的「慢更或断更 · 待查」为 0 时隐藏，它只在有 UP 主需要查时才存在。
- 标签行（第 4 行）：只列当前页签里有视频带着的标签。筛选已经打开的标签照样显示，方便关掉。「已失效」「AI 刚打的」这类条件片，数量为 0 时隐藏。
- 「全选」「标题粗看这 N 个」里的 N 只算你现在看得见的，也就是经过搜索和筛选之后剩下的。被筛掉的视频不受影响，它们的选中状态也保留。

## 5. 改 B站 的操作和撤销

- U 只撤销当前模式里的操作，不会撤到另一个模式。切换收藏夹只清掉收藏夹的步骤，关注的不受影响；删除标签会清掉这个模式里改标签的步骤。
- 单个操作不弹确认，提供按 U 撤销，比如取消收藏、特别关注、单个「重新关注」。撤销重新关注会在 B站再取消关注，「已取消关注」里的记录和标签照原样放回。
- 单个「取消关注」例外，要弹确认，因为重新关注后原来的关注时间就没了。
- 批量操作要弹确认。确认框标题以「在 B站」开头，按钮上写数量，比如「取消关注 12 个」。
- 只改扩展本地数据的操作（标签、备注、AI 建议）都能按 U 撤销。一次操作算一步，比如关一次打标签面板就是一步。
- 要撤销的这一步改了 2 个以上对象时，撤销前先确认，比如批量保留、批量取消收藏、批量特别关注（整批算一步）、AI 打标签、选中栏的「标签…」。
- 标签只存在扩展里，不改 B站。B站 的关注分组只读。

## 6. 用词

下面的用词表和时间格式管的是分拣台。

| 用 | 不用 |
|---|---|
| 刷新 | 更新、同步（按钮上） |
| 标签管理 | 管理标签 |
| ✦ AI 打标签 | 批量打、标签 |
| 在 B站打开 | 去 B站、打开原视频 |
| 收藏夹设置 / 关注设置 | 分拣设置、设置（单独出现时） |
| 导出 | 批量导出（作为入口名时） |
| 摘录或笔记…（导出菜单里那一项，按产出命名） | 批量导出… |
| 判断标准 | 标准、规则 |
| 播放列表（临时的待看清单，跨收藏夹，不参与导出） | 优先看 |
| B站分拣台 | 收藏夹分拣台 |

时长写成 `1:15:00` 或 `9:47`。数量写成 `12.3万`、`2.5亿`。「刷新过」的时间写成「今天 HH:MM」。卡片上的时间在列表里写相对时间（「1 天前」），悬停显示具体日期。

- 待办：导出菜单那一项和它的弹窗现在还叫「批量导出」，要改成「摘录或笔记…」。
- 其他页面有自己的格式：历史页写 `2026/10/09 14:05`，侧边栏的对话时间写 `2026-10-09 14:05`，popup 的创建日期写 `2026-10-09`。
- 「只更新 AI 问答」（导出笔记时的选项）是替换笔记里的一段，不算刷新，不用改成「刷新」。

## 7. 代码怎么共用

- 两种模式都画的东西，只在 `extension/triage/shared.js`（`TriageUi`）里写一份：标题行、排序、搜索框、筛选片、刷新和导出按钮、进度胶囊、空状态、设置行、格式化函数、标签名清洗、标签颜色、AI 建议的合并。发现两边各写了一份，就合并进去。
- 打标签面板只有一个：`extension/triage/tag-picker.js`。例外：B站 页面上的「+」标签面板（`badges.js`）在封闭的 shadow DOM 里，暂时用不了 tag-picker.js，它自己又写了一份标签颜色和标签名清洗。计划：先把这些纯函数抽到一个小文件里，在 `badges.js` 之前加载，以后再迁过去。「标签管理」和「✦ AI 打标签」弹窗也各只有一个：`extension/triage/tag-dialogs.js`。模式打开它们时只传一个 adapter，里面是单位（视频 / UP 主）、上限和数据，文字和布局都在弹窗里。
- 所有输入框和快捷键都要走 `extension/typing.js`（`BocTyping`）：
  - 回车和 Esc 的处理函数，开头先写 `if (BocTyping.composing(e)) return;`。
  - 全局快捷键，开头写 `if (composing(e) || typingIn(e)) return;`。
  - 实时过滤的输入框用 `bindLive`。列表的搜索框用 `TriageUi.bindSearch`：Esc 清空，空框再按 Esc 移出焦点。
  - 这样以后新加的输入框，用输入法打字也不会出问题。
- 键盘只有一个全局处理函数，在 `triage.js` 的 `onKey` 里。播放器里按的 T / Esc 也只有一个 message 监听，同在 `triage.js`。关注模式用 `MoonTriage.setModeKeys` 注册自己的按键，两处都先问它。
- B站 的请求只走现有的通道：风控码统一用 `BILI_RISK_CODES`，WBI 签名用 `sites.js`。
