# MoonDigest 工程约定

这里记的是代码怎么组织、哪些东西只写一份。界面和交互的规则看 [DESIGN.md](DESIGN.md)。

B站 页面上的颜色是 `tokens.css` 的第三份拷贝：`content.css` 里的 `--mdg-*`（`content-tokens.selftest.js` 会核对）和 `badges.css` 里直接写的色值（也由 `content-tokens.selftest.js` 核对，新写死的色值要加进它的 `BADGE_TOKENS` 表）。改 token 时，在同一个 PR 里把这两处一起改。

## 代码怎么共用

- 两种模式都画的东西，只在 `extension/triage/shared.js`（`TriageUi`）里写一份：标题行、排序、搜索框、筛选片、第 3/4 行的行名（`labeledRow`）、第 4 行的标签片（`tagFilterChip`）、「已出分拣范围」的原因页签（`kindTabs`）、卡片上的「原在…」（`originChip`）、「清理」按钮（`cleanBtn`）和清理前的备份说法（`CLEAN_BACKUP`）、「AI 刚打的」片（`aiRecentChip`）、选中栏（`selbar`）、移动 / 复制弹窗（`askTransfer`：收藏夹传收藏夹，关注传分组）、左栏项（`sideItem`）、刷新和导出按钮、进度胶囊、空状态和里面的刷新（`refreshEmpty`）、头部收起（`headFold`，两种模式各自记在 `triage_head_folded`；列表滚动后加 `head-scrolled` 画头部下沿的阴影；它返回的函数由 `follow.js` 的 `setMode` 在切换 `body.follow-mode` 后立刻调用，新模式的收起状态不播动画地生效）、列表为空的原因（`noMatch`）、撤销前的确认（`undoAsk`）、设置行（`fillSetRows`，包括「AI 打标签每批数量」，数字框的范围和「默认 N」、提示里的数字（`data-num-min` / `data-num-max` / `data-num-default`）都来自 `NUM_SETTINGS`；提示里的数字由 `fillNumHints` 填，设置页 `options.html` 也加载 `shared.js` 用它；提示里引用的固定数（粗看一次请求带几个标题 `TriageUi.TITLES_PER_REQUEST`、粗看和 AI 打标签带的简介字数 `INTRO_CHARS`、细看没字幕时读的热门评论条数 `DEEP_COMMENTS`、笔记的热门评论条数、快捷追问和正文附加段落的上限、AI 读的字幕字数）写成 `data-hint-num`，也由 `fillNumHints` 从代码填）、输出上限留空时的「自动」（`autoMaxTokens`：粗看、AI 打标签、细看各一条公式，后台 `triageMaxTokens` 发请求和收藏夹设置的提示都用；AI 打标签读粗看的输出上限设置）、格式化函数、AI 建议的合并（标签名清洗和标签颜色在 `extension/tag-core.js`）。「收藏夹设置」和「关注设置」两个弹窗的结构都写在 `triage.html` 里。发现两边各写了一份，就合并进去。
- 打标签面板只有一个：`extension/triage/tag-picker.js`。例外：B站 页面上的「+」标签面板（`badges.js`）在封闭的 shadow DOM 里，暂时用不了 tag-picker.js，标签的纯函数（颜色、标签名清洗、新标签 id、下一个颜色）放在 `extension/tag-core.js`（`MdgTagCore`）里，`badges.js`、`shared.js`、`follow.js` 和 `fav-*.js` 都用它，manifest 和 `triage.html` 都在它们之前加载。`tag-core.selftest.js` 会查别处有没有再写一份。面板本身以后再迁到 tag-picker.js。「标签管理」和「✦ AI 打标签」弹窗也各只有一个：`extension/triage/tag-dialogs.js`；关注的「分组管理」也用「标签管理」这个弹窗，adapter 换掉标题、文字和每行的样子。模式打开它们时只传一个 adapter，里面是单位（视频 / UP 主 / 记录）、上限和数据，文字、布局和确认页的计数（改动数、按标签汇总、「用在 N 个」）都在弹窗里。摘读记录页也用这三个（打标签面板、「标签管理」、「✦ AI 打标签」）：页面里只放空的 `<dialog>`，「✦ AI 打标签」的结构由 `tag-dialogs.js` 写进去，两个页面共用一份；摘读记录没有 T，确认页和「AI 刚打的」提示里「不对的按 T 改」那半句由 adapter 的 `check` 换掉。
- 标签的数据操作只有一份：`extension/triage/tag-store.js`（`MdgTagStore`），`triage.html` 和 `history.html` 都加载它。新建、改名、换颜色、改说明、删除（确认框的个数）、给条目加减标签、上限和原因、AI 的新建名额（`room` / `noRoom`）、U 的步骤（`pushStep` / `undoLast`，收藏夹的保留和改 B站 的步骤也走这两个）、「✦ AI 打标签」的批次（`runAi`）和「应用」（`apply`：先写，写成了才清建议、标「AI 刚打的」、压 U；写失败留着建议、红字说）都在里面。每个页面 `MdgTagStore.create(adapter)` 一次，adapter 只说不一样的：数据在哪（三种后端：收藏夹 `local`，内存加页面自己的 `store`；关注 `follow`，`MdgLimits.updateFollow` 的锁；摘读记录 `marks`，`MdgLimits.updateReadingMarks`，星标也走它的 `update`）、条目（哪些 `live`；关注的已取消关注算进个数 `uses`，U 不改他们 `restorable`）、作用域（收藏夹按收藏夹，`scoped`）、上限和超了怎么办（`hardCap`：摘读记录给出「摘读记录的标签」，超了不建并在确认页说；收藏夹和关注不给，照建）、名词。删掉一个标签（标签管理、U 删掉没人用的新标签）都调页面的 `tagGone`，收藏夹在别的标签页删了标签时（`followShared`）也走它；关注的后端在删标签的同一次写里把它从已取消关注 UP 主的 `follow_unfollowed` 记录上去掉。`conventions.selftest.js` 的 5c 查页面文件不直接写标签键、不自建撤销栈。B站 页面（`badges.js`）和后台不用它，用 `tag-core.js` 的 `applyUpTag`。
- 标签和这些弹窗的样式只有一份：`extension/triage/tags.css`（标签片、打标签面板、「标签管理」「✦ AI 打标签」和它们所在的 `<dialog>`），`triage.html` 和 `history/history.html` 都在自己的样式表之后加载它。`<dialog>` 的规则写成 `dialog:where(:not(.mdg-overwrite))`，和原来的 `dialog` 一样具体，又不碰 `tokens.css` 管的「该笔记已存在」。挪进来时分拣台每个元素的计算样式一项不差（页面、三个弹窗和分拣台的其他弹窗逐个核对过）；摘读记录的打标签面板和「标签管理」因此和分拣台一样了。
- 摘读记录页的头部和卡片用分拣台的样子：`history.html` 在 `history.css` 之前加载 `triage/triage.css`，头部的行名、筛选片、`.act-btn`、全选、搜索框、选中栏、`.card`、`.badge` 和空状态都用它的规则和 `TriageUi` 的标记（`labeledRow`、`stateGroup`、`filterBtn`、`aiRecentChip`、`tagFilterChip`、`tagButtons`、`gearBtn`、`selectAllBox`、`selbar`、`actBtn`、`searchBox`、`bindSearch`、`resultCount`、`cardTagChip`、`emptyState`、`noMatch`）；`history.css` 只写页面的排法、头部白卡和卡片里的列。分拣台的头部靠四行各自的 `::before` 拼成白卡（列表从底下滚过），摘读记录是窗口滚动、头部不收起，所以白卡就是一个 `<header>` 的边框，不用那套拼法。改 `triage.css` 里这些规则时两个页面一起看。
- 所有输入框和快捷键都要走 `extension/typing.js`（`MdgTyping`）：
  - 回车和 Esc 的处理函数，开头先写 `if (MdgTyping.composing(e)) return;`。
  - 全局快捷键，开头写 `if (composing(e) || typingIn(e)) return;`。
  - 实时过滤的输入框用 `bindLive`。列表的搜索框用 `TriageUi.bindSearch`：Esc 清空，空框再按 Esc 移出焦点。
  - 这样以后新加的输入框，用输入法打字也不会出问题。
- 键盘只有一个全局处理函数，在 `fav-page.js` 的 `onKey` 里。内置播放框里按的 T / Esc 也只有一个 message 监听，同在 `fav-page.js`。关注模式用 `MoonTriage.setModeKeys` 注册自己的按键，两处都先问它。
- 内置播放框的 × 不放在 `#viewer` 里，而是紧跟在它后面的同一个格子（grid-area `viewer`）里，因为 `#viewer` 要 `overflow: hidden` 裁出圆角；`#viewer[hidden]` 时 CSS 把它一起藏起来。
- B站 页面上画什么只写一份：`badges.js` 的 `surfaceOf` 认出是哪种页面（首页和搜索、收藏夹、稍后再看和历史、动态、UP 空间、视频页、分拣台内置播放框），`bili-surfaces.js` 的 `SURFACES` 写每种页面显示哪些东西（设置页的表格也读它），顶栏弹窗按元素认（`.bew-popover`、`.v-popover`）。标签放得下多少只有一个函数：`fitCount` 算个数，`fitBoxes` 量宽度、藏掉放不下的、写「+N」，`ResizeObserver` 在容器变宽变窄时重量。观看进度的设置怎么读（`seenConfig`）和封面上的字（「✓ 看完了」「✓ 看到 N%」「看到 N%」，`seenWords`）也只写在 `bili-surfaces.js`，B站 页面、分拣台和设置页的示例都用它（`triage.html` 和 `options.html` 也加载它）。观看进度的三个默认值只在 `settings.js` 的 `DEFAULTS`，「封面显示」的合法值只在 `MdgSettings.SEEN_SHOW`（读它用 `normalizeSeenShow`，开没开只用 `seenOn`，后台、设置页和观看进度的读取都用），「看完了标记样式」（角标 / 封面遮罩）的合法值只在 `MdgSettings.SEEN_STYLES`（读它用 `normalizeSeenStyle`，默认值在 `DEFAULTS`），B站 页面的标记开关也经 `normalizeSwitches` 读；「看到多少算看完了」的范围和默认值只在 `MdgSettings.SEEN_THRESHOLD`，读它只用 `MdgSettings.normalizeSeenThreshold`（后台、`seenConfig`、设置页都用；设置页数字框的范围和「默认 N」也从这里填）。后台、B站 页面的标记脚本、分拣台和设置页都先加载 `settings.js`。算百分比的函数分两处：后台 `triage-bg.js` 的 `seenPercent` 算历史记录，分拣台 `fav-folders.js` 的 `seenPercentOf` 先看历史、再看稍后再看自带的进度（`toviewPercent`）；观看进度关着时卡片信息行的稍后再看进度（`seenText`）也用 `toviewPercent` 和 `seenWords`，不另算。
- B站 页面上什么时候画：`badges.js` 在 document_start 注入（排在 `viewer-frame.js` 后面，它先给播放框打上 `data-mdg-viewer`），一开始就把要用的存储读进内存（`getKeys` 的键表、标签和决定、收藏夹页这个收藏夹快照里每个视频的结果、视频页这个视频的结果），之后 `MutationObserver` 只看新加的节点，在它的回调里（画面出来之前）从内存标好（`onMutations` → `run(roots)`）；B站 自己重画时拿掉的标记也在同一个回调里补回。视频页和 `/list/` 播放页是服务器渲染的：`#app` 带着 `data-server-rendered`，Vue 接管（水合）时一步去掉它。UP 名字下那一行要等它去掉再画：接管前插进去会让接管出错，播放器的网页全屏和评论区跟着坏（#394）。`#app` 里别的标记（标题下那一行、卡片上的）照旧提前画，接管前插进去没弄坏过页面，晚画反而会让卡片跳。属性去掉是 `#app` 上的一次变化，整个 `#app` 重看一遍。播放器里的变化（弹幕）不进队列，我们自己的悬停说明（`.mdg-pop`）和「+」面板（`.mdg-tagpick-host`）加上、拿掉也不进。视频页标题下那一行带 `data-key`（它显示的内容），内容变了才重画。`ResizeObserver` 只重量尺寸变了的容器里的标记；动态卡片的作者（`nameMid`）按名字节点记住，名字或关注数据变了才重算。整页重看只在开头、站内换页、标签页切回来、一次回调超过 100 个节点和数据变了（`schedule`，400ms 节流）时做。别处有自己结果的视频要等一次读取，晚一两帧。
- 内置播放框下的标签行只有一种写法：`TriageUi.viewerLine`，行名用第 3/4 行的 `labeledRow`。收藏夹的「视频标签」行在 `fav-tags.js`，「UP 标签」行在 `follow.js`，收藏夹每次画完自己那行就通过 `MoonTriage.setViewerHook` 让关注重画 UP 那行；B站 自动连播换了视频时（`fav-page.js` 的 `showViewing`），关注也在这个 hook 里把 `F.viewing` / `F.viewingMid` 换成新视频。
- 后台（`background.js` 的 service worker）也加载 `tag-core.js` 和 `shared.js`，日期、时长、标签名清洗和关注分组名的上限与检查（`GROUP_NAME_MAX`、`groupNameError`）直接用 `TriageUi`，不在 `triage-bg.js`、`follow-bg.js` 里另写。弹窗也加载 `shared.js`，时长用 `TriageUi.fmtDuration`。笔记、弹窗和视频页共用的去句尾标点只在 `sites.js`（`trimReason`）。视频上下文的字段（标题、地址、站点和视频 id、分 P、选中的字幕）怎么整理也只在这里：`MdgSites.contextRef`，后台写笔记、读上下文和侧边栏存对话、画占位上下文都用它；它的网址（去掉专注模式和跟踪参数、带分 P）只由 `MdgSites.videoUrl` 拼，笔记、后台和视频页都用它。标签名最长几个字只有 `MdgTagCore.TAG_NAME_MAX`，各个标签名输入框都读它。B站 页面的标记开关默认值读 `MdgSettings.DEFAULTS`。加载顺序以 `background.js` 的 `importScripts` 为准，后台的 selftest 照它读；侧边栏、摘读记录页和视频页的 selftest 同样照 `sidepanel.html`、`history/history.html` 和 manifest 里 `content.js` 那一项读，不手写脚本清单。
- 「✦ AI 打标签」的后台只有一份：`triage-bg.js` 的 `triageAiCommand`（指令检查、新建上限按 `numSetting("newTagMax")` 取值、解析）。关注只把 UP 主整理成条目，带上自己的 unit 调它。摘读记录页自己把记录整理成条目（`history.js` 的 `aiItem`：标题、视频还是网页、现有标签和对话的问答，按 `TriageUi.READING_AI_CHARS` 截；没有对话的带分拣台的 AI 总结和备注），发 `triage-reading-ai-tag`，后台带 `READING_AI_UNIT` 调它；条目按 `id`（`MdgNote.readingKey`）认，没有 `id` 的按 `bvid`（`triageItemId`）。摘读记录的批次也走 `runs.js`（`history.html` 加载它，页面自己一个实例，没有胶囊，倒计时写在弹窗和状态文字里），用同一个 `MdgRuns.aiJudge`：限流倒计时重发、超时重发一次、设置类错误停下给「去设置」或「授权」。它的设置存在 sync 的 `KEYS.readingAiSettings`，读法和关注的 `follow_ai_settings` 同一个（`FollowCore.followAiSettings`：第一次用时照搬 `triage-settings-get` 的收藏夹值并存下，之后只读自己的），所以 `history.html` 也加载 `follow-core.js`；建议和「AI 刚打的」存在 local 的 `readingAiProposal` / `readingAiRecent`，U 的步骤只在页面内存里（`tag-store.js` 自己的栈，最多 `TRIAGE_UNDO_STEPS` 步）。设置行的样式（`.set-row` 等）在 `tags.css`，三个设置弹窗共用。
- 选哪个 AI 平台只有一处记：侧边栏顶部的选择存在扩展页面的 `localStorage`（`MdgLimits.KEYS.aiSelectedProvider`）。分拣台的每个请求由 `fav-base.js` 的 `sendRaw` 带上它（`aiProviderId`），后台的 `triageChat`（`triageProvider`）用它，没选或已停用就用第一个启用的平台，和侧边栏一样。收藏夹设置的「开启思考」显示不显示也跟着它：每次打开收藏夹设置都重新问一次 `triage-settings-get`，侧边栏换了平台不用重开分拣台。
- 分拣台的长任务只有一个循环：`extension/triage/runs.js`（`MdgRuns.create`），每种模式一个实例（`fav-base.js` 和 `follow.js` 的 `runs`）。粗看、细看、AI 打标签（两种模式和摘读记录，`MdgTagStore` 的 `runAi`）、逐个视频笔记、「已出分拣范围」的核对、两边改 B站 的批量写和关注「视频投稿」的限流等待都是它的 `run` 或 `wait`：一个任务名同一时间只跑一个（第二个被拒并报出在跑的名字）、请求之间留间隔、限流时倒计时再重发同一个请求、暂停 / 停止 / 切换收藏夹在间隔和倒计时里立即生效、做完的个数由它数。每个回答怎么算由任务的 `judge` 定：AI 的超时和限流怎么数只有 `MdgRuns.aiJudge`（每次跑各数各的），粗看、细看、AI 打标签和摘读记录的 AI 打标签共用；等不等按这次运行实例的 `hold`（分拣台是 `THROTTLES`，细看遇到 B站 限流也等）。例外：「所有收藏夹」的加载（`runLoadAll`）两条队列会轮换、暂停后能接着跑，留着自己的循环，只用 `runs.wait` 等限流。

- 读一个视频（字幕、评论、分拣台的附加内容）有三处：视频页（`content.js`）、侧边栏接着问 AI（`background.js` 的 `resolveAiSidepanelContext`）和分拣台的细看 / 笔记（`triage-bg.js` 的 `triageAnalyze` / `triageBuildNote`）。它们共用这些，不各写一份：
  - 字幕时长检查只有 `MdgSites.validateSubtitleByDuration`。对不上的字幕照样用，配视频页那句「字幕时间轴到 X，视频长 Y，字幕时间可能对不上。」（`MdgNote.subtitleMismatchWarning`），只是不进字幕缓存；没有时长就不查。
  - 字幕这一步只有一份：`MdgSites.loadSubtitle`，三处都用它，怎么挑轨、怎么抓、怎么查、什么算失败什么算限流都在这里。读字幕轨列表，按 `io.subtitleLang` 排序，`prefer`（上次选的那条）放第一；`MdgSites.loadFirstTrack` 按顺序试，第一条和视频时长对得上的就用（进字幕缓存）。都对不上时再读一次列表、再试一遍（字幕文件为空时第二次不带 PO token）；还不行或列表没读到（如拿不到 PO token），YouTube 试视频页的文字稿；最后用第一条对不上的，带回 `mismatch`。限流（`THROTTLED` 或 HTTP 429）立即停下不再试别的轨，也不读 YouTube 的文字稿，第二次读列表时碰到也一样：手里有对不上的就用它，没有就抛出，调用方等一会再试。其他失败（断网、超时、链接过期、字幕文件为空）不报错，带回 `error` 和 `failure`（去掉句号的原因）；B站 因为没登录不给字幕时带回 `needLogin`，它是单独的状态，不算失败。三种没有字幕的说法只在 `MdgErrors.subtitleMissing` 写一份，三处和笔记都用它。`step(promise)` 包住每一次等待，视频页靠它在换了视频后停下（`runStep`，作废的读取抛 `STALE_RUN`）；`io.fresh` 让视频页的读取不读缓存。
  - 视频页只多一层自己的抓取（`pageSubtitleSite`）：字幕列表重试 3 次，B站 回空列表时 1.5 秒后再问一次（后台不做：分拣台批量里每个没字幕的视频都会多一个请求和 1.5 秒，更容易碰到风控），后台请求被当成没登录时用页面的 cookie 再问；字幕文件 429 先等 3–5 秒重试一次，再 429 时 B站 报 `THROTTLED`（「B站限流，请稍后再试」，`biliJson` 已认好，带着 HTTP 状态），YouTube 报 `TEXT.ytThrottled`（「YouTube 限流，请稍后再试」）。换字幕（`switchSubtitle`）也走这层，所以字幕文件 429 一样等一下重试一次、说同一句限流。限流不降级成没有字幕：`runRefreshClip` 只在别的字幕失败时进 `showNoSubtitleState`，限流时整次读取失败（红字、「重试」），不生成笔记、不读评论，和侧边栏、「逐个视频笔记」一样。视频页把结果放进 `state`（`showSubtitle`），没有字幕时显示原因（`showNoSubtitleState`）；每次读取开始时先清掉上次的字幕状态（失败原因、未登录、时长提示）和热门评论，所以同一个视频重读后笔记不带上次的话。没有字幕轨时，专注模式和弹窗的字幕下拉框、弹窗「下载字幕」灰掉的原因都读 `noTrackText`：读取中写 `TEXT.subtitleReading`（「正在读取视频字幕…」，侧边栏同一句），读取失败写「读取视频失败」，读完才是 `subtitleMissing` 的三种。换字幕（`switchSubtitle`）只试选中的那一条（`loadFirstTrack`），读缓存。`content.selftest.js` 核对 `content.js` 不再自己写一份挑轨流程。

- 收藏夹的页面是 `extension/triage/` 下的普通脚本 `fav-*.js`，按 `triage.html` 的加载顺序：`fav-base.js`（常量、状态 `S` / `el` / `runs`、存储和消息的读写、提示和确认框、卡片从 `S` 派生的东西和排序）、`fav-folders.js`（观看进度、打开和从 B站 读收藏夹、已出分拣范围、所有收藏夹）、`fav-render.js`（侧栏、收藏夹头、标签页、第 3 行、卡片列表和焦点）、`fav-writes.js`（保留和取消收藏、撤销、`fav` 的 B站 写）、`fav-tags.js`（标签、判断标准、标签管理）、`fav-ai.js`（标题粗看、字幕细看、AI 打标签）、`fav-export.js`（摘录或笔记、CSV、完整备份）、`fav-page.js`（启动 `start`、给关注的 `MoonTriage`、待播、事件和按键）。它们顶层的名字都是分拣台页面的全局变量，各文件直接互相读写，所以拆开只是按节分文件，各节之间的耦合没变。一个文件加载时执行的代码只能用前面文件的名字，函数体里的不限。模块 `triage.js` 在它们之后执行，只有三行：开发预览里先载入假的 `chrome.*`，再 `init()` 启动。所以 `fav-*.js` 加载时不碰 `chrome.*`，要读假数据设的值（B站限流等多久）时现用现读。`triage.selftest.js` 和 `follow.selftest.js` 照 `triage.html` 的顺序执行这些脚本，顺序不对会报 `ReferenceError`。
- 收藏夹的纯函数放在 `extension/triage/triage-core.js`（`TriageCore`），`fav-*.js` 只留页面部分（DOM、存储、状态、计时）。现在里面是存储数据的形状（已出分拣范围的 `updateRemoved` / `moveToRemoved`、所有收藏夹的 `mergeFolderItems`、缓存列表的 `mergeHead` / `idsChanged` / `keepInvalidInfo` 等）和导出用的 Markdown 链接、zip 打包（`zipStored`）。放进去的函数只按参数算，不碰 DOM、`chrome.*`、`S` / `el` / `K` 和计时器；要改签名才算得上纯的留在 `fav-*.js`。`triage.html` 在 `fav-*.js` 之前加载它，`triage.selftest.js` 照 `triage.html` 的脚本清单加载（只跳过它自己替身的 `tag-dialogs.js`），并核对每个读 `TriageCore` 的页面先加载它。后台不用它。
- 关注的纯函数放在 `extension/triage/follow-core.js`（`FollowCore`）：更新状态、UP 主行和筛选、分组、排序、动态列表、标签和 AI 设置的整理。规矩同 `TriageCore`，只按参数和 `TriageUi` 算；`follow.js` 只留页面部分，开头从 `FollowCore` 取它用的名字。`triage.html` 在 `follow.js` 之前加载它，后台在 `follow-bg.js` 之前 `importScripts` 它（取关记录里的分组用同一个 `groupsOf`），`follow.selftest.js` 直接加载它测。
- 撤销步骤只有一个形状 `{ kind, ask, blocked?, undo }`（`fav-writes.js` 的 `pushUndo` 上面写着）：`undo()` 撤掉自己、返回提示，`ask` 是改了多个视频时先问的那句，`blocked()` 说为什么现在不能撤。收藏夹本地的那几种（保留、标签、AI 打标签、待播）用 `pageStep` 建，B站 写用 `favStep`，关注的 kind 是 `"mode"`、放在自己的栈里。U 只走一条路：问、弹出、`undo()`。加一种撤销只改推入的地方。
- 改 B站 的批量写在 `runs.js` 上面一层：`extension/triage/writes.js`（`MdgWrites.create`）只管写的规则，每个 adapter 一条自己的跑道（lane），各自的撤销栈，互不挡：收藏夹（`fav-writes.js` 的 `fav`，键是 bvid，lane `fav`）和关注（`follow.js` 的 `relationRun`，键是 mid，lane `follow-write`）。两边胶囊上的「停止」都是 `W.stop()`，按下后变成「停止中」，灰掉的原因只有 `TriageUi.WRITE_STOPPING` 一份。
- 收藏夹改 B站 的写操作只有一条路：`fav-writes.js` 的 `fav`（`unfav` 单个取消收藏、`unfavMany` 批量取消收藏、`transfer` 移动 / 复制 / 收藏到、`refav` 单个重新收藏、`refavBatch` 这批全部重新收藏、`state()` 给渲染和读取用），请求由 `writes.js` 发。`writes.js` 不碰 `S` / `el` / DOM，也不认识收藏夹：批量按块发（循环、间隔、限流重发同一块、停在失败的那块都是 `runs.js` 的）、哪些视频在等写（`pending`）、哪些收藏夹刚写过不能读（`writing`：批量在写它，或 3 秒内写过，单个写遇到限流的那次也算）。块怎么切也只在 `fav` 里一处（`chunkSize` / `chunkGap`：稍后再看和从已出分拣范围收藏到每次一个、间隔 300 ms，别的 20 个、间隔 1 秒）；后台 `triage-bg.js` 照样能收一组，因为 B站 稍后再看的接口本来就一次一个。撤销这些写的步骤自己带 `undo()`、`ask` 和 `blocked()`（批量在跑时不能撤）。`writes.selftest.js` 在 node 里测写的规则，`triage.selftest.js` 经 `fav.*`、U 和画出来的按钮测页面，`follow.selftest.js` 测 `relationRun`。收藏夹里的番剧（`resource/list` 里 type 24，要带 `platform=web` 才列出来）和视频一样进分拣台，只按稿件层认：bvid 用列表给的，`aid` 是这个 bvid 的稿件 aid（type 24 的 `id` 是集 id，不用），另记 `ogv: true`。写 B站 时怎么称呼它只在两处：页面的 `fav-base.js` `favRes`（番剧发 `aid:42`，视频发 aid），后台的 `triage-bg.js` `triageRes`（收藏夹的写和「核对视频的收藏状态」发 `aid:42` / `aid:2`，稍后再看发 aid）。B站 对存成 `集id:24` 的那条收藏也认 `aid:42`，所以同一集在哪个收藏夹、在不在稍后再看都用同一个 aid；稍后再看的列表按 `redirect_url` 指向 `/bangumi/` 或带 `pgc_label` 标番剧（`season_id` 视频也可能带 0，不认它），从稍后再看移到收藏夹也发 `aid:42`（发 `aid:2` B站 不拒，会存成一条怪的视频）；`mergeFolderItems` 只要有一处标了就算番剧。`resource/ids` 给 type 24 的 bvid 是拿集 id 当 aid 算的、是别的视频：列表条目另记 `ep`（`id:type`），后台 `triageFolderIds` 按刚读的列表、这个收藏夹的缓存和已出分拣范围把 ids 里的番剧换回 bvid，页面拿到的 ids 和视频一样全是 bvid（失效后从列表消失、还在 ids 里的番剧照样算失效，没变的收藏夹也不会因为番剧被当成变了）；哪里都没记过的番剧留着 `id:type`，不会和任何视频对上。
