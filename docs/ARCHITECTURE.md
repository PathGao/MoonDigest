# MoonDigest 工程约定

这里记的是代码怎么组织、哪些东西只写一份。界面和交互的规则看 [DESIGN.md](DESIGN.md)。

B站 页面上的颜色是 `tokens.css` 的第三份拷贝：`content.css` 里的 `--mdg-*`（`content-tokens.selftest.js` 会核对）和 `badges.css` 里直接写的色值（也由 `content-tokens.selftest.js` 核对，新写死的色值要加进它的 `BADGE_TOKENS` 表）。改 token 时，在同一个 PR 里把这两处一起改。

## 代码怎么共用

- 两种模式都画的东西，只在 `extension/triage/shared.js`（`TriageUi`）里写一份：标题行、排序、搜索框、筛选片、第 3/4 行的行名（`labeledRow`）、第 4 行的标签片（`tagFilterChip`）、「已出分拣范围」的原因页签（`kindTabs`）、卡片上的「原在…」（`originChip`）、「清理」按钮（`cleanBtn`）和清理前的备份说法（`CLEAN_BACKUP`）、「AI 刚打的」片（`aiRecentChip`）、选中栏（`selbar`）、移动 / 复制弹窗（`askTransfer`：收藏夹传收藏夹，关注传分组）、左栏项（`sideItem`）、刷新和导出按钮、进度胶囊、空状态和里面的刷新（`refreshEmpty`）、头部收起（`headFold`，两种模式各自记在 `triage_head_folded`；列表滚动后加 `head-scrolled` 画头部下沿的阴影；它返回的函数由 `follow.js` 的 `setMode` 在切换 `body.follow-mode` 后立刻调用，新模式的收起状态不播动画地生效）、列表为空的原因（`noMatch`）、撤销前的确认（`undoAsk`）、设置行（`fillSetRows`，包括「AI 打标签每批数量」，数字框的范围和「默认 N」、提示里的数字（`data-num-min` / `data-num-max` / `data-num-default`）都来自 `NUM_SETTINGS`；提示里的数字由 `fillNumHints` 填，设置页 `options.html` 也加载 `shared.js` 用它；提示里引用的固定数（粗看一次请求带几个标题 `TriageUi.TITLES_PER_REQUEST`、粗看和 AI 打标签带的简介字数 `INTRO_CHARS`、细看没字幕时读的热门评论条数 `DEEP_COMMENTS`、笔记的热门评论条数、快捷追问和正文附加段落的上限、AI 读的字幕字数）写成 `data-hint-num`，也由 `fillNumHints` 从代码填）、输出上限留空时的「自动」（`autoMaxTokens`：粗看、AI 打标签、细看各一条公式，后台 `triageMaxTokens` 发请求和收藏夹设置的提示都用；AI 打标签读粗看的输出上限设置）、格式化函数、AI 建议的合并（标签名清洗和标签颜色在 `extension/tag-core.js`）。「收藏夹设置」和「关注设置」两个弹窗的结构都写在 `triage.html` 里。发现两边各写了一份，就合并进去。
- 打标签面板只有一个：`extension/triage/tag-picker.js`。例外：B站 页面上的「+」标签面板（`badges.js`）在封闭的 shadow DOM 里，暂时用不了 tag-picker.js，标签的纯函数（颜色、标签名清洗、新标签 id、下一个颜色）放在 `extension/tag-core.js`（`MdgTagCore`）里，`badges.js`、`shared.js`、`follow.js` 和 `triage.js` 都用它，manifest 和 `triage.html` 都在它们之前加载。`tag-core.selftest.js` 会查别处有没有再写一份。面板本身以后再迁到 tag-picker.js。「标签管理」和「✦ AI 打标签」弹窗也各只有一个：`extension/triage/tag-dialogs.js`；关注的「分组管理」也用「标签管理」这个弹窗，adapter 换掉标题、文字和每行的样子。模式打开它们时只传一个 adapter，里面是单位（视频 / UP 主）、上限和数据，文字、布局和确认页的计数（改动数、按标签汇总、「用在 N 个」）都在弹窗里。
- 所有输入框和快捷键都要走 `extension/typing.js`（`MdgTyping`）：
  - 回车和 Esc 的处理函数，开头先写 `if (MdgTyping.composing(e)) return;`。
  - 全局快捷键，开头写 `if (composing(e) || typingIn(e)) return;`。
  - 实时过滤的输入框用 `bindLive`。列表的搜索框用 `TriageUi.bindSearch`：Esc 清空，空框再按 Esc 移出焦点。
  - 这样以后新加的输入框，用输入法打字也不会出问题。
- 键盘只有一个全局处理函数，在 `triage.js` 的 `onKey` 里。内置播放框里按的 T / Esc 也只有一个 message 监听，同在 `triage.js`。关注模式用 `MoonTriage.setModeKeys` 注册自己的按键，两处都先问它。
- 内置播放框的 × 不放在 `#viewer` 里，而是紧跟在它后面的同一个格子（grid-area `viewer`）里，因为 `#viewer` 要 `overflow: hidden` 裁出圆角；`#viewer[hidden]` 时 CSS 把它一起藏起来。
- B站 页面上画什么只写一份：`badges.js` 的 `surfaceOf` 认出是哪种页面（首页和搜索、收藏夹、稍后再看和历史、动态、UP 空间、视频页、分拣台内置播放框），`bili-surfaces.js` 的 `SURFACES` 写每种页面显示哪些东西（设置页的表格也读它），顶栏弹窗按元素认（`.bew-popover`、`.v-popover`）。标签放得下多少只有一个函数：`fitCount` 算个数，`fitBoxes` 量宽度、藏掉放不下的、写「+N」，`ResizeObserver` 在容器变宽变窄时重量。观看进度的设置怎么读（`seenConfig`）和封面上的字（「✓ 看完了」「✓ 看到 N%」「看到 N%」，`seenWords`）也只写在 `bili-surfaces.js`，B站 页面、分拣台和设置页的示例都用它（`triage.html` 和 `options.html` 也加载它）。观看进度的三个默认值只在 `settings.js` 的 `DEFAULTS`，「封面显示」的合法值只在 `MdgSettings.SEEN_SHOW`（读它用 `normalizeSeenShow`，开没开只用 `seenOn`，后台、设置页和观看进度的读取都用），「看完了标记样式」（角标 / 封面遮罩）的合法值只在 `MdgSettings.SEEN_STYLES`（读它用 `normalizeSeenStyle`，默认值在 `DEFAULTS`），B站 页面的标记开关也经 `normalizeSwitches` 读；「看到多少算看完了」的范围和默认值只在 `MdgSettings.SEEN_THRESHOLD`，读它只用 `MdgSettings.normalizeSeenThreshold`（后台、`seenConfig`、设置页都用；设置页数字框的范围和「默认 N」也从这里填）。后台、B站 页面的标记脚本、分拣台和设置页都先加载 `settings.js`。算百分比的函数分两处：后台 `triage-bg.js` 的 `seenPercent` 算历史记录，分拣台 `triage.js` 的 `seenPercentOf` 先看历史、再看稍后再看自带的进度（`toviewPercent`）；观看进度关着时卡片信息行的稍后再看进度（`seenText`）也用 `toviewPercent` 和 `seenWords`，不另算。
- 内置播放框下的标签行只有一种写法：`TriageUi.viewerLine`，行名用第 3/4 行的 `labeledRow`。收藏夹的「视频标签」行在 `triage.js`，「UP 标签」行在 `follow.js`，收藏夹每次画完自己那行就通过 `MoonTriage.setViewerHook` 让关注重画 UP 那行；B站 自动连播换了视频时（`triage.js` 的 `showViewing`），关注也在这个 hook 里把 `F.viewing` / `F.viewingMid` 换成新视频。
- 后台（`background.js` 的 service worker）也加载 `tag-core.js` 和 `shared.js`，日期、时长、标签名清洗和关注分组名的上限与检查（`GROUP_NAME_MAX`、`groupNameError`）直接用 `TriageUi`，不在 `triage-bg.js`、`follow-bg.js` 里另写。弹窗也加载 `shared.js`，时长用 `TriageUi.fmtDuration`。笔记、弹窗和视频页共用的去句尾标点只在 `sites.js`（`trimReason`）。视频上下文的字段（标题、地址、站点和视频 id、分 P、选中的字幕）怎么整理也只在这里：`MdgSites.contextRef`，后台写笔记、读上下文和侧边栏存对话、画占位上下文都用它；它的网址（去掉专注模式和跟踪参数、带分 P）只由 `MdgSites.videoUrl` 拼，笔记、后台和视频页都用它。标签名最长几个字只有 `MdgTagCore.TAG_NAME_MAX`，各个标签名输入框都读它。B站 页面的标记开关默认值读 `MdgSettings.DEFAULTS`。加载顺序以 `background.js` 的 `importScripts` 为准，后台的 selftest 照它读；侧边栏、视频记录页和视频页的 selftest 同样照 `sidepanel.html`、`history/history.html` 和 manifest 里 `content.js` 那一项读，不手写脚本清单。
- 「✦ AI 打标签」的后台只有一份：`triage-bg.js` 的 `triageAiCommand`（指令检查、新建上限按 `numSetting("newTagMax")` 取值、解析）。关注只把 UP 主整理成条目，带上自己的 unit 调它。
- 选哪个 AI 平台只有一处记：侧边栏顶部的选择存在扩展页面的 `localStorage`（`MdgLimits.KEYS.aiSelectedProvider`）。分拣台的每个请求由 `triage.js` 的 `sendRaw` 带上它（`aiProviderId`），后台的 `triageChat`（`triageProvider`）用它，没选或已停用就用第一个启用的平台，和侧边栏一样。收藏夹设置的「开启思考」显示不显示也跟着它：每次打开收藏夹设置都重新问一次 `triage-settings-get`，侧边栏换了平台不用重开分拣台。
- 分拣台的长任务只有一个循环：`extension/triage/runs.js`（`MdgRuns.create`），每种模式一个实例（`triage.js` 和 `follow.js` 的 `runs`）。粗看、细看、AI 打标签（两种模式，`runAiBatches`）、逐个视频笔记、「已出分拣范围」的核对、两边改 B站 的批量写和关注「视频投稿」的限流等待都是它的 `run` 或 `wait`：一个任务名同一时间只跑一个（第二个被拒并报出在跑的名字）、请求之间留间隔、限流时倒计时再重发同一个请求、暂停 / 停止 / 切换收藏夹在间隔和倒计时里立即生效、做完的个数由它数。每个回答怎么算由任务的 `judge` 定：AI 的超时和限流怎么数只有 `aiJudge`（每次跑各数各的），粗看、细看、AI 打标签共用。例外：「所有收藏夹」的加载（`runLoadAll`）两条队列会轮换、暂停后能接着跑，留着自己的循环，只用 `runs.wait` 等限流。
  - 进度胶囊只从它画：`runs.pill(顺序)` 取第一个在跑、在等或有行的任务，都没有再取跑完留下的绿色结果行；等限流时一律在进度后面接「· B站限流卡住，m:ss 后重试」。别处来的状态（关注的后台刷新和它的「B站限流变慢」、观看进度、刷新中、标签建议待确认、「所有收藏夹」的加载）用 `runs.put` 放一行进去。收藏夹的顺序是 `triage.js` 的 `PILL`，按钮是 `PILL_BTN`；关注的在 `follow.js` 的 `renderSync` 旁边。第 3 行的「暂停粗看 N/M」也读 `runs.get`。
  - 限流等多久只有 `hold`：收藏夹是 `triage.js` 的 `THROTTLES`（`MoonTriage.hold`），关注的 B站限流是 90 秒的 `TriageUi.BILI_HOLD_MS`。后台的队列暂停（`follow_jobs.hold`、`follow_hold`）和观看进度的 30 分钟来自后台存储，不走它。`runs.selftest.js` 在 node 里用假时钟测它。
- 后台的 B站 GET 只走 `triage-bg.js` 的 `triageBiliGetJson`（带 B站 的 referrer、不缓存），30 秒没回应算断网（「网络断了：30 秒没有回应」，时长和文字是 `MdgErrors.NET_TIMEOUT_MS` / `netTimeout`，视频页自己发的请求 `fetchOk` 也用这一份）。细看（`triageAnalyze`）、生成笔记（`triageBuildNote`）和侧边栏接着问 AI 的上下文（`resolveAiSidepanelContext`）都经 `TRIAGE_BILI_IO` 走它（WBI 签名）。视频页的 `fetch-json` 代理也走它（不带 pace，只试一次，由视频页重试），失败时把 `code` 和 HTTP 状态一起回给视频页，所以视频页和分拣台、侧边栏读同一个视频失败时写的是同一句（「B站请求失败 HTTP 403」「B站返回的不是 JSON（…）」）。认 B站 限流只有一处：`sites.js` 的 B站 读取都经 `biliJson`，把 HTTP 412、HTTP 429、风控码和「播放器接口回了却没有字幕对象」算成 `THROTTLED`（文字是 `MdgErrors.TEXT.biliThrottled`），视频页、分拣台和侧边栏读同一个视频都经它，所以 B站 限流报成限流，不会变成「没有字幕」，也不再去请求备用接口。收藏夹每次只试一次，限流由页面退避；关注传入自己的队列（间隔、断网重试、风控整队暂停）。写操作 `triageBiliPost` 也有这 30 秒超时，但只发一次、从不自动重试；超时报「不确定 B站 是否已改」，调用方按失败处理，不改计数、不记撤销。风控码统一用 `BILI_RISK_CODES`，WBI 签名用 `sites.js`。
- 页面怎么显示一个错误只写一份：`extension/errors.js`（`MdgErrors`）。后台负责分类（`triage-bg.js` 的 `triageAiHttpError`、HTTP 200 里的错误 `triageAiBodyError`、AI 平台没填的项 `aiProviderProblem`，侧边栏、测试连接和分拣台都用它们；`obsidian.js` 的 `obsidianError`），回 `{ ok: false, error, code }`；页面用 `MdgErrors.action(code)` 决定给「去设置」还是「去登录」（Obsidian 没启用、没配置、Key 不对或地址回 404 是 `OBSIDIAN`，给「去设置」；没打开是 `OBSIDIAN_DOWN`，不给），`MdgErrors.text` / `fromResp` 读出要显示的话（B站 的 62004 换成「视频审核中，过后再试」；没登录 B站 一律是 `TEXT.biliLogin`：后台的 `NOT_LOGGED_IN` 由 `triage-bg.js` 的 `triageNotLoggedIn` 建，关注那边 B站 回 -101 时 `follow-bg.js` 也换成它，所以各阶段都停下，不当成「暂时没查到」），缺 AI 平台地址的访问权限时后台回 code `AI_ACCESS`（分拣台按它停下，不认文字；请求没回应时是 `AI_ACCESS` 还是 `AI_NETWORK` 只在 `triage-bg.js` 的 `aiFetchError` 分），模型输出被截断回 `AI_TRUNCATED`（分拣台按它提示调大输出上限），`grantOrigin` 从「未授权访问 …」读出地址并给出授权按钮的请求，`reloaded` 认出扩展更新后内容脚本失效。表里的错误码按名字导出成 `MdgErrors.CODE`（写或比较 `THROTTLED`、`AI_SETUP` 的地方用它，不手打），超时的 HTTP 状态 408 是 `MdgErrors.TIMEOUT_STATUS`。HTML 转义也只有这里一份：`MdgErrors.escapeHtml` 转 `& < > " '` 五个字符，页面、视频页和分拣台（`TriageUi.esc` 就是它）拼 HTML 都用它，`errors.selftest.js` 查别处有没有再写一份；`badges.js` 用 `textContent` 建 DOM，不需要它。Obsidian 的几句话（包括取消时那句）和「扩展刚刚更新，请刷新网页」只写在 `MdgErrors.TEXT` 里，后台也读它。它也是全扩展的文字表：多个页面都显示的句子在 `TEXT`，按钮名和页面名（复制 Markdown、下载 .md、写入 Obsidian、去设置、重试、刷新、视频记录、B站分拣台、已保留、已取消收藏、新标签名称）在 `LABEL`，html 的静态副本标 `data-text="键"`；规则见 DESIGN.md 术语表一节。内容脚本、后台和每个用到它的页面都在用它的脚本之前加载 `errors.js`（`load-order.selftest.js` 核对），`wording.selftest.js` 查别处有没有再写一份这些话（`TriageUi`、`MdgLimits` 里有名字的句子常量也一样），也查同一句话有没有在两个页面各写一份（现有的在文件里的 `DUPLICATES`，每条写明文件和「待修」或「例外」的理由，新出现的失败）和术语表里「不用」的词（只查能和普通文字分开的那些，见 `TERMS`）。按钮灰掉写原因（`disabled`、tooltip 和 `aria-description`）也只有这里一份：`MdgErrors.setReason`，分拣台（`TriageUi.setReason` 就是它）、弹窗、侧边栏和视频记录页都用它，`errors.selftest.js` 查别处有没有再写一份。
- 设置的默认值和整理函数只写一份：`extension/settings.js`（`MdgSettings`）。`DEFAULTS`（sync）和 `LOCAL_DEFAULTS`（Obsidian 的 Key）是唯一一份默认值，默认的 AI 提示词也只写在这里；后台 `normalizeSyncSettings` 用它存设置，页面和内容脚本只在 get-settings 失败时拿 `DEFAULTS` 兜底。安装和更新不把默认值写进 sync，读的时候补（`getMergedSettings`、`sync.get(DEFAULTS)`），所以改了默认值，没改过这项的人都会拿到新的；以前写进去的不迁移。几个页面都要的整理函数（API Key、下载格式、AI 总结要求、快捷追问和它的 12 条上限、自定属性、正文附加段落、专注模式的主题和四个档位：合法值只在 `READER_OPTIONS`，默认值在 `DEFAULTS`，视频页的档位按钮和主题切换都读它）也在这里，字符串一律按 `String(v ?? "")` 处理，数字保留。开关（`DEFAULTS` 里是布尔值的设置）怎么取值也只在这里（`normalizeSwitches`）：默认开的只有存的是 `false` 才关，默认关的只有存的是 `true` 才开，导入文件里的 `"true"` 这类非布尔值一律按默认值，后台 `normalizeSyncSettings` 存和读都先过它，笔记（`note.js` 的封面、AI 问答、热门评论、文件名日期）和专注模式的章节开关也经它读，专注模式的初始值读 `DEFAULTS`。设置文件的导出和导入都经后台的 `withoutApiKeys`，去掉 Obsidian 和 AI 平台的 Key（包括平台条目里带的 `apiKey`），Key 只存本机。数字设置不对时怎么取值（`intIn`：空、不是数字、小于下限用默认值，大于上限用上限，四舍五入）也只在这里，`TriageUi.intIn` 就是它，`normalizeSeenThreshold` 也用它，所以凡是加载 `shared.js` 的地方都先加载 `settings.js`。设置页自己的表单检查留在 `options.js`。`note.js` 也读它，所以凡是加载 `note.js` 的地方都先加载 `settings.js`；加载顺序由 `load-order.selftest.js` 核对；`settings.selftest.js` 查别处有没有再写一份默认提示词或这些函数。

- 读一个视频（字幕、评论、分拣台的附加内容）有三处：视频页（`content.js`）、侧边栏接着问 AI（`background.js` 的 `resolveAiSidepanelContext`）和分拣台的细看 / 笔记（`triage-bg.js` 的 `triageAnalyze` / `triageBuildNote`）。它们共用这些，不各写一份：
  - 字幕时长检查只有 `MdgSites.validateSubtitleByDuration`。对不上的字幕照样用，配视频页那句「字幕时间轴到 X，视频长 Y，字幕时间可能对不上。」（`MdgNote.subtitleMismatchWarning`），只是不进字幕缓存；没有时长就不查。
  - 字幕这一步只有一份：`MdgSites.loadSubtitle`，三处都用它，怎么挑轨、怎么抓、怎么查、什么算失败什么算限流都在这里。读字幕轨列表，按 `io.subtitleLang` 排序，`prefer`（上次选的那条）放第一；`MdgSites.loadFirstTrack` 按顺序试，第一条和视频时长对得上的就用（进字幕缓存）。都对不上时再读一次列表、再试一遍（字幕文件为空时第二次不带 PO token）；还不行或列表没读到（如拿不到 PO token），YouTube 试视频页的文字稿；最后用第一条对不上的，带回 `mismatch`。限流（`THROTTLED` 或 HTTP 429）立即停下不再试别的轨，也不读 YouTube 的文字稿，第二次读列表时碰到也一样：手里有对不上的就用它，没有就抛出，调用方等一会再试。其他失败（断网、超时、链接过期、字幕文件为空）不报错，带回 `error` 和 `failure`（去掉句号的原因）；B站 因为没登录不给字幕时带回 `needLogin`，它是单独的状态，不算失败。三种没有字幕的说法只在 `MdgErrors.subtitleMissing` 写一份，三处和笔记都用它。`step(promise)` 包住每一次等待，视频页靠它在换了视频后停下（`runStep`，作废的读取抛 `STALE_RUN`）；`io.fresh` 让视频页的读取不读缓存。
  - 视频页只多一层自己的抓取（`pageSubtitleSite`）：字幕列表重试 3 次，B站 回空列表时 1.5 秒后再问一次（后台不做：分拣台批量里每个没字幕的视频都会多一个请求和 1.5 秒，更容易碰到风控），后台请求被当成没登录时用页面的 cookie 再问；字幕文件 429 先等 3–5 秒重试一次，再 429 时 B站 报 `THROTTLED`（「B站限流，请稍后再试」，`biliJson` 已认好，带着 HTTP 状态），YouTube 报「字幕接口限流（429）」。换字幕不走这层，B站 的 429 也经 `biliJson` 报成同一句限流。限流不降级成没有字幕：`runRefreshClip` 只在别的字幕失败时进 `showNoSubtitleState`，限流时整次读取失败（红字、「重试」），不生成笔记、不读评论，和侧边栏、「逐个视频笔记」一样。视频页把结果放进 `state`（`showSubtitle`），没有字幕时显示原因（`showNoSubtitleState`）；每次读取开始时先清掉上次的字幕状态（失败原因、未登录、时长提示）和热门评论，所以同一个视频重读后笔记不带上次的话。没有字幕轨时，专注模式和弹窗的字幕下拉框、弹窗「下载字幕」灰掉的原因都读 `noTrackText`：读取中写 `TEXT.subtitleReading`（「正在读取视频字幕…」，侧边栏同一句），读取失败写「读取视频失败」，读完才是 `subtitleMissing` 的三种。换字幕（`switchSubtitle`）只试选中的那一条（`loadFirstTrack`），读缓存。`content.selftest.js` 核对 `content.js` 不再自己写一份挑轨流程。
  - 分拣台的细看和笔记因此按简介和评论来：`triageAnalyze` 把原因记在 `subtitleFailure` 给卡片，发给 AI 的说明也是 `subtitleMissing` 那一句，没登录或抓取失败时和侧边栏一样提醒 AI 视频可能有字幕（这句提醒只在 `triage-bg.js` 的 `aiSubtitleMissing`），`triageBuildNote` 照写笔记（`noteMeta.subtitleFailure`，和视频页笔记同一句开头），`subtitleWarning` 带上那句话（「字幕抓取失败：原因。」或「未登录 B站，拿不到字幕。」），视频记录页、侧边栏和「逐个视频笔记」都显示它。侧边栏接着问 AI（`resolveAiSidepanelContext`）也一样，把原因放进 `subtitleFailure`，和视频页传给侧边栏的字段同名，侧边栏照视频页那样写「字幕抓取失败」。

  - 后台两处的笔记字段由 `MdgNote.noteMetaOf` 从 `sites.js` 的结果拼出（章节没有时从简介里解析，和视频页一样）。
  - 分拣台的附加内容（AI 总结只给 B站 P1、备注、分拣标签）由 `MdgNote.triageExtrasKeys` 列出要读的键、`MdgNote.triageExtras` 取出来；视频页、分拣台笔记和侧边栏的 AI 笔记都用它。视频记录页一次读出全部存储再按视频分组，不走它。
- 视频页的「当前视频」只有一个入口：`content.js` 的 `settledClip(force)`。弹窗、侧边栏、播放器上的 ✦ 和专注模式都经它读：先跑一次 `checkUrlChange`，让状态跟上标签页的地址（URL 轮询每 1.2 秒一次，中间不会拿到上一个视频，也不会再起一次读取）；有在跑的读取就等它，没有时只在 `force`（「刷新」）或还没读过时才起一个；被换视频作废的读取不算数（`checkUrlChange` 同时清掉 `refreshPromise`），等接替它的那次，或给现在的视频起一次；最后给现在这个视频的结果或它的失败。作废的读取晚到的失败（超时、限流、字幕失败）直接丢掉，不碰新视频的状态（`runRefreshClip` 的 catch 先比 `runId`）。
  - 页面和后台之间只有一条上下文消息：`sidepanel-get-context { refresh }`，内容脚本用 `clipContext` 回完整的上下文，热门评论也在里面（有就用 `state.hotComments`，没有就在这次读取里抓；抓的时候换了视频就重来，不会配上别的视频的评论）。后台 `getAiSidepanelState` 只发这一条，`ok: false` 就把 `error` 抛给侧边栏。弹窗用 `popup-refresh { refresh }`，也走 `settledClip`。打开弹窗、侧边栏跟着标签页时都不带 force，只有「刷新」带。
  - 分拣台的内置播放框也走这个入口。它的 ✦ 和专注模式的 AI 总结经后台交给侧边栏时，后台把 `sender.frameId` 和视频一起放进请求；侧边栏照常按视频打开它的对话（有存过的就打开最近那段），读这段对话的上下文时先问那个框：`ai-sidepanel-get-state { tabId, frameId, videoId }`，后台把 `sidepanel-get-context` 只发给那个框，所以框里选的字幕就是 AI 读的字幕；每次发问前再问一次。框关了，或自动连播换成了别的视频（内容脚本见 `videoId` 对不上就不回），就和关掉的视频页一样，由后台按视频去读（`resolveAiSidepanelContext`），侧边栏也不再问这个框。不用 `webNavigation` 权限。
  - 换字幕只有 `switchSubtitle`（弹窗和专注模式的下拉框）：字幕地址不在当前 `state.subtitles` 里就回「视频已切换，请刷新」；时长对不上的字幕照样用，带上提示；连着换几次时只显示最后选的那条，先选的晚到也不覆盖它。
- 侧边栏的对话和它的上下文只在 `extension/sidepanel-state.js`（`SidepanelState`）里：显示哪段对话、它绑定哪个视频、跟随播放（`decideFollow`）、AI 还在回答时离开（回答跟着原对话走，只有删除才丢掉）、输入框草稿属于对话（换对话就清空）、AI 总结什么时候填进输入框（跟随到空对话后、上下文到了才填，每段对话一次）、占位上下文都带 `pending`、对话自己的上下文和标签页是同一个视频就用标签页的，否则去读；一个字没收到就失败或停止的问题不存，但记着，重画时照画；别的窗口的侧边栏后存了同一段对话，就换成它存的消息。它是纯的：不碰 `chrome.*` 和 DOM。显示的上下文不存，按对话推出来；换对话只有 `setConv` 一处，换了就加 `epoch`，晚到的读取按 `epoch` 作废。`sidepanel.js` 只是外壳：读标签页、存储、回答流（port）、计时器、Obsidian、备注、平台和快捷追问、弹层和画界面；它把发生的事 `dispatch` 进去，照返回的 effects 做（断开回答流、存对话、清草稿、填 AI 总结、读对话的上下文、设上一个视频……），画界面时对话和上下文只读 `view()`。规则的测试在 `sidepanel-state.selftest.js`（只用事件，不碰 DOM）；`sidepanel.selftest.js` 测外壳，并查 `sidepanel.js` 没有再声明这些状态。
- 发给 AI 的视频上下文只有一个写法：`note.js` 的 `MdgNote.buildAiContext`（视频页 `content.js` 和后台 `resolveAiSidepanelContext` 共用）。它就是笔记（`buildMarkdown`）去掉热门评论和播放器嵌入；嵌入只给 Obsidian，写入和下载的笔记照常带着。
- 收藏夹的纯函数放在 `extension/triage/triage-core.js`（`TriageCore`），`triage.js` 只留页面部分（DOM、存储、状态、计时）。现在里面是存储数据的形状（已出分拣范围的 `updateRemoved` / `moveToRemoved`、所有收藏夹的 `mergeFolderItems`、缓存列表的 `mergeHead` / `idsChanged` / `keepInvalidInfo` 等）和导出用的 Markdown 链接、zip 打包（`zipStored`）。放进去的函数只按参数算，不碰 DOM、`chrome.*`、`S` / `el` / `K` 和计时器；要改签名才算得上纯的留在 `triage.js`。`triage.html` 在 `triage.js` 之前加载它，`triage.selftest.js` 照 `triage.html` 的脚本清单加载（只跳过它自己替身的 `tag-dialogs.js`），并核对每个读 `TriageCore` 的页面先加载它。后台不用它。
- 撤销步骤只有一个形状 `{ kind, ask, blocked?, undo }`（`triage.js` 的 `pushUndo` 上面写着）：`undo()` 撤掉自己、返回提示，`ask` 是改了多个视频时先问的那句，`blocked()` 说为什么现在不能撤。收藏夹本地的那几种（保留、标签、AI 打标签、待播）用 `pageStep` 建，B站 写用 `favStep`，关注的 kind 是 `"mode"`、放在自己的栈里。U 只走一条路：问、弹出、`undo()`。加一种撤销只改推入的地方。
- 改 B站 的批量写在 `runs.js` 上面一层：`extension/triage/writes.js`（`MdgWrites.create`）只管写的规则，每个 adapter 一条自己的跑道（lane），各自的撤销栈，互不挡：收藏夹（`triage.js` 的 `fav`，键是 bvid，lane `fav`）和关注（`follow.js` 的 `relationRun`，键是 mid，lane `follow-write`）。两边胶囊上的「停止」都是 `W.stop()`，按下后变成「停止中」，灰掉的原因只有 `TriageUi.WRITE_STOPPING` 一份。
- 收藏夹改 B站 的写操作只有一条路：`triage.js` 的 `fav`（`unfav` 单个取消收藏、`unfavMany` 批量取消收藏、`transfer` 移动 / 复制 / 收藏到、`refav` 单个重新收藏、`refavBatch` 这批全部重新收藏、`state()` 给渲染和读取用），请求由 `writes.js` 发。`writes.js` 不碰 `S` / `el` / DOM，也不认识收藏夹：批量按块发（循环、间隔、限流重发同一块、停在失败的那块都是 `runs.js` 的）、哪些视频在等写（`pending`）、哪些收藏夹刚写过不能读（`writing`：批量在写它，或 3 秒内写过，单个写遇到限流的那次也算）。块怎么切也只在 `fav` 里一处（`chunkSize` / `chunkGap`：稍后再看和从已出分拣范围收藏到每次一个、间隔 300 ms，别的 20 个、间隔 1 秒）；后台 `triage-bg.js` 照样能收一组，因为 B站 稍后再看的接口本来就一次一个。撤销这些写的步骤自己带 `undo()`、`ask` 和 `blocked()`（批量在跑时不能撤）。`writes.selftest.js` 在 node 里测写的规则，`triage.selftest.js` 经 `fav.*`、U 和画出来的按钮测页面，`follow.selftest.js` 测 `relationRun`。
