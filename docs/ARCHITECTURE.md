# MoonDigest 工程约定

这里记的是代码怎么组织、哪些东西只写一份。界面和交互的规则看 [DESIGN.md](DESIGN.md)。

B站 页面上的颜色是 `tokens.css` 的第三份拷贝：`content.css` 里的 `--mdg-*`（`content-tokens.selftest.js` 会核对）和 `badges.css` 里直接写的色值（也由 `content-tokens.selftest.js` 核对，新写死的色值要加进它的 `BADGE_TOKENS` 表）。改 token 时，在同一个 PR 里把这两处一起改。

## 代码怎么共用

- 两种模式都画的东西，只在 `extension/triage/shared.js`（`TriageUi`）里写一份：标题行、排序、搜索框、筛选片、第 3/4 行的行名（`labeledRow`）、第 4 行的标签片（`tagFilterChip`）、「已出分拣范围」的原因页签（`kindTabs`）、卡片上的「原在…」（`originChip`）、「清理」按钮（`cleanBtn`）、「AI 刚打的」片（`aiRecentChip`）、选中栏（`selbar`）、移动 / 复制弹窗（`askTransfer`：收藏夹传收藏夹，关注传分组）、左栏项（`sideItem`）、刷新和导出按钮、进度胶囊、空状态和里面的刷新（`refreshEmpty`）、头部收起（`headFold`，两种模式各自记在 `triage_head_folded`）、列表为空的原因（`noMatch`）、撤销前的确认（`undoAsk`）、设置行（`fillSetRows`，包括「AI 打标签每批数量」，数字框的范围和「默认 N」、提示里的数字（`data-num-min` / `data-num-max` / `data-num-default`）都来自 `NUM_SETTINGS`）、格式化函数、AI 建议的合并（标签名清洗和标签颜色在 `extension/tag-core.js`）。「收藏夹设置」和「关注设置」两个弹窗的结构都写在 `triage.html` 里。发现两边各写了一份，就合并进去。
- 打标签面板只有一个：`extension/triage/tag-picker.js`。例外：B站 页面上的「+」标签面板（`badges.js`）在封闭的 shadow DOM 里，暂时用不了 tag-picker.js，标签的纯函数（颜色、标签名清洗、新标签 id、下一个颜色）放在 `extension/tag-core.js`（`MdgTagCore`）里，`badges.js`、`shared.js`、`follow.js` 和 `triage.js` 都用它，manifest 和 `triage.html` 都在它们之前加载。`tag-core.selftest.js` 会查别处有没有再写一份。面板本身以后再迁到 tag-picker.js。「标签管理」和「✦ AI 打标签」弹窗也各只有一个：`extension/triage/tag-dialogs.js`；关注的「分组管理」也用「标签管理」这个弹窗，adapter 换掉标题、文字和每行的样子。模式打开它们时只传一个 adapter，里面是单位（视频 / UP 主）、上限和数据，文字、布局和确认页的计数（改动数、按标签汇总、「用在 N 个」）都在弹窗里。
- 所有输入框和快捷键都要走 `extension/typing.js`（`MdgTyping`）：
  - 回车和 Esc 的处理函数，开头先写 `if (MdgTyping.composing(e)) return;`。
  - 全局快捷键，开头写 `if (composing(e) || typingIn(e)) return;`。
  - 实时过滤的输入框用 `bindLive`。列表的搜索框用 `TriageUi.bindSearch`：Esc 清空，空框再按 Esc 移出焦点。
  - 这样以后新加的输入框，用输入法打字也不会出问题。
- 键盘只有一个全局处理函数，在 `triage.js` 的 `onKey` 里。内置播放框里按的 T / Esc 也只有一个 message 监听，同在 `triage.js`。关注模式用 `MoonTriage.setModeKeys` 注册自己的按键，两处都先问它。
- 内置播放框的 × 不放在 `#viewer` 里，而是紧跟在它后面的同一个格子（grid-area `viewer`）里，因为 `#viewer` 要 `overflow: hidden` 裁出圆角；`#viewer[hidden]` 时 CSS 把它一起藏起来。
- B站 页面上画什么只写一份：`badges.js` 的 `surfaceOf` 认出是哪种页面（首页和搜索、收藏夹、稍后再看和历史、动态、UP 空间、视频页、分拣台内置播放框），`bili-surfaces.js` 的 `SURFACES` 写每种页面显示哪些东西（设置页的表格也读它），顶栏弹窗按元素认（`.bew-popover`、`.v-popover`）。标签放得下多少只有一个函数：`fitCount` 算个数，`fitBoxes` 量宽度、藏掉放不下的、写「+N」，`ResizeObserver` 在容器变宽变窄时重量。观看进度的默认值、设置怎么读（`seenConfig`）和封面上的字（「✓ 看完了」「✓ 看到 N%」「看到 N%」，`seenWords`）也只写在 `bili-surfaces.js`，B站 页面、分拣台和设置页的示例都用它（`triage.html` 和 `options.html` 也加载它）；这三个默认值和 `settings.js` 的 `DEFAULTS` 各一份，`settings.selftest.js` 核对一致。算百分比的函数分两处：后台 `triage-bg.js` 的 `seenPercent` 算历史记录，分拣台 `triage.js` 的 `seenPercentOf` 先看历史、再看稍后再看自带的进度。
- 内置播放框下的标签行只有一种写法：`TriageUi.viewerLine`，行名用第 3/4 行的 `labeledRow`。收藏夹的「视频标签」行在 `triage.js`，「UP 标签」行在 `follow.js`，收藏夹每次画完自己那行就通过 `MoonTriage.setViewerHook` 让关注重画 UP 那行；B站 自动连播换了视频时（`triage.js` 的 `showViewing`），关注也在这个 hook 里把 `F.viewing` / `F.viewingMid` 换成新视频。
- 后台（`background.js` 的 service worker）也加载 `tag-core.js` 和 `shared.js`，日期、时长、标签名清洗直接用 `TriageUi`，不在 `triage-bg.js` 里另写。加载顺序以 `background.js` 的 `importScripts` 为准，后台的 selftest 照它读；侧边栏、视频记录页和视频页的 selftest 同样照 `sidepanel.html`、`history/history.html` 和 manifest 里 `content.js` 那一项读，不手写脚本清单。
- 「✦ AI 打标签」的后台只有一份：`triage-bg.js` 的 `triageAiCommand`（指令检查、新建上限 0–50、解析）。关注只把 UP 主整理成条目，带上自己的 unit 调它。
- 选哪个 AI 平台只有一处记：侧边栏顶部的选择存在扩展页面的 `localStorage`（`mdg_ai_selected_provider`）。分拣台的每个请求由 `triage.js` 的 `sendRaw` 带上它（`aiProviderId`），后台的 `triageChat` 用它，没选或已停用就用第一个启用的平台，和侧边栏一样。
- 分拣台的长任务只有一个循环：`extension/triage/runs.js`（`MdgRuns.create`），每种模式一个实例（`triage.js` 和 `follow.js` 的 `runs`）。粗看、细看、AI 打标签（两种模式，`runAiBatches`）、逐个视频笔记、「已出分拣范围」的核对、两边改 B站 的批量写和关注「视频投稿」的限流等待都是它的 `run` 或 `wait`：一个任务名同一时间只跑一个（第二个被拒并报出在跑的名字）、请求之间留间隔、限流时倒计时再重发同一个请求、暂停 / 停止 / 切换收藏夹在间隔和倒计时里立即生效、做完的个数由它数。每个回答怎么算由任务的 `judge` 定：AI 的超时和限流怎么数只有 `aiJudge`（每次跑各数各的），粗看、细看、AI 打标签共用。例外：「所有收藏夹」的加载（`runLoadAll`）两条队列会轮换、暂停后能接着跑，留着自己的循环，只用 `runs.wait` 等限流。
  - 进度胶囊只从它画：`runs.pill(顺序)` 取第一个在跑、在等或有行的任务，都没有再取跑完留下的绿色结果行；等限流时一律在进度后面接「· B站限流卡住，m:ss 后重试」。别处来的状态（关注的后台刷新和它的「B站限流变慢」、观看进度、刷新中、标签建议待确认、「所有收藏夹」的加载）用 `runs.put` 放一行进去。收藏夹的顺序是 `triage.js` 的 `PILL`，按钮是 `PILL_BTN`；关注的在 `follow.js` 的 `renderSync` 旁边。第 3 行的「暂停粗看 N/M」也读 `runs.get`。
  - 限流等多久只有 `hold`：收藏夹是 `triage.js` 的 `THROTTLES`（`MoonTriage.hold`），关注的 B站限流是 90 秒的 `TriageUi.BILI_HOLD_MS`。后台的队列暂停（`follow_jobs.hold`、`follow_hold`）和观看进度的 30 分钟来自后台存储，不走它。`runs.selftest.js` 在 node 里用假时钟测它。
- 后台的 B站 GET 只走 `triage-bg.js` 的 `triageBiliGetJson`（带 B站 的 referrer、不缓存），30 秒没回应算断网（「网络断了」）。细看（`triageAnalyze`）、生成笔记（`triageBuildNote`）和侧边栏接着问 AI 的上下文（`resolveAiSidepanelContext`）都经 `TRIAGE_BILI_IO` 走它（WBI 签名），另把风控码和「播放器接口回了却没有字幕对象」算成限流，所以 B站 限流报成限流，不会变成「没有字幕」。`background.js` 的 `fetchJsonForAi` 只剩视频页的 `fetch-json` 代理。收藏夹每次只试一次，限流由页面退避；关注传入自己的队列（间隔、断网重试、风控整队暂停）。写操作 `triageBiliPost` 也有这 30 秒超时，但只发一次、从不自动重试；超时报「不确定 B站 是否已改」，调用方按失败处理，不改计数、不记撤销。风控码统一用 `BILI_RISK_CODES`，WBI 签名用 `sites.js`。
- 页面怎么显示一个错误只写一份：`extension/errors.js`（`MdgErrors`）。后台负责分类（`triage-bg.js` 的 `triageAiHttpError`、`obsidian.js` 的 `obsidianError`），回 `{ ok: false, error, code }`；页面用 `MdgErrors.action(code)` 决定给「去设置」还是「去登录」（Obsidian 没配置或 Key 不对是 `OBSIDIAN`，给「去设置」；没打开是 `OBSIDIAN_DOWN`，不给），`MdgErrors.text` / `fromResp` 读出要显示的话（B站 的 62004 换成「视频审核中，过后再试」），`grantOrigin` 认出「未授权访问 …」并给出授权按钮的请求，`reloaded` 认出扩展更新后内容脚本失效。HTML 转义也只有这里一份：`MdgErrors.escapeHtml` 转 `& < > " '` 五个字符，页面、视频页和分拣台（`TriageUi.esc` 就是它）拼 HTML 都用它，`errors.selftest.js` 查别处有没有再写一份；`badges.js` 用 `textContent` 建 DOM，不需要它。Obsidian 的几句话（包括取消时那句）和「扩展刚刚更新，请刷新网页」只写在 `MdgErrors.TEXT` 里，后台也读它。内容脚本、后台和每个用到它的页面都在用它的脚本之前加载 `errors.js`（`load-order.selftest.js` 核对），`errors.selftest.js` 查别处有没有再写一份这些话。例外：`badges.js` 不加载它，自己照抄一份「扩展刚刚更新，请刷新网页」，selftest 核对两份一字不差。
- 设置的默认值和整理函数只写一份：`extension/settings.js`（`MdgSettings`）。`DEFAULTS`（sync）和 `LOCAL_DEFAULTS`（Obsidian 的 Key）是唯一一份默认值，默认的 AI 提示词也只写在这里；后台 `normalizeSyncSettings` 用它存设置，页面和内容脚本只在 get-settings 失败时拿 `DEFAULTS` 兜底。几个页面都要的整理函数（API Key、下载格式、AI 总结要求、快捷追问和它的 12 条上限、自定属性、正文附加段落、阅读视图）也在这里，字符串一律按 `String(v ?? "")` 处理，数字保留。设置页自己的表单检查留在 `options.js`。`note.js` 也读它，所以凡是加载 `note.js` 的地方都先加载 `settings.js`；加载顺序由 `load-order.selftest.js` 核对；`settings.selftest.js` 查别处有没有再写一份默认提示词或这些函数。
- AI 判断的三类（值得留 / 可清理 / 拿不准）和怎么判只写一份：`extension/tag-core.js` 的 `VERDICTS` 和 `verdictOf`（细看优先于粗看，已失效一律可清理）。分拣台（`triage.js`）、B站 页面（`badges.js`）、后台（`triage-bg.js` 认模型的回答）和笔记里的「AI 判断：…」（`note.js`）都读它，所以凡是加载 `note.js` 的地方也先加载 `tag-core.js`，加载顺序由 `load-order.selftest.js` 核对，`tag-core.selftest.js` 查别处有没有再写一份。B站 页面只在收藏夹页知道哪些视频已失效（读这个收藏夹的 `triage_snapshot_<fid>`）；别的页面不读，所有收藏夹的快照太大。
- 写入 Obsidian 只有一个写入者：后台的 `extension/obsidian.js`（`background.js` 在 `triage-bg.js` 之前 `importScripts` 它）。读写库（Local REST API）、错误分类（`obsidianError`）、把封面存进库、记住每个视频写到哪篇笔记都在这里，页面不碰库。视频页、侧边栏、视频记录页和「逐个视频笔记」都发同一条消息 `write-video-note { ref, mode?, conversation?, page? }`，同名函数 `writeVideoNote` 走一条流程：设置（没开、没配置、Key 不对是 `OBSIDIAN`，没打开是 `OBSIDIAN_DOWN`）→ 路径（先用记住的路径，没有再用 `MdgNote.videoNotePath`；对话笔记用 `MdgNote.conversationNotePath`）→ 正文（有 `page` 用 `page.markdown`，没有就用 `triageBuildNote` 生成 B站 P1 笔记；YouTube、分 P、已失效的视频没开视频页，或关了「附带 AI 问答」时用户自己写的对话，写成单独的对话笔记）→ 读一次库 → 回 `ask { path, hasAiSection }`、`ok { path, kind, text }` 或 `failed { error, code }`。`mode` 不给时笔记已存在就回 `ask`；`full` 整篇写（AI 问答段换成这次的对话、封面存进库、一次 PUT、记住路径）；`ai` 只换 AI 问答段，笔记不存在时整篇写。结果那句话（字幕提示 + 已写入 Obsidian / 已更新 AI 问答 + 路径）只在这里拼。取消靠结构：页面收到 `ask`、用户取消，就不发第二条，什么都不写。「逐个视频笔记」不带对话，按「覆盖已有笔记」发 `full` 或 `ai`，所以从不问。侧边栏每次回答完发 `sync-video-note-ai`，只更新记住路径的那篇，从不新建。`obsidian-sync.selftest.js` 用假的 Local REST API 测这条流程，并查页面里没有别的库请求、`resolveFolderTemplate(` 只在 `note.js`、`obsidian.js` 和 `triage-export` 里。「一篇摘录」和索引（`triage-export`）、开跑前的检查（`triageObsidianCheck`）和设置页的「测试连接」各自直接写或查，也用 `obsidian.js` 的读写和错误分类。
- 「该笔记已存在」确认框在扩展页面上只有一个：`extension/download.js` 的 `MdgOverwriteDialog.choose`（原生 `<dialog>`，样式在 `tokens.css`），侧边栏和视频记录页收到 `ask` 时都用它；三种情况（有 AI 问答可更新、没有 AI 问答可更新、对话笔记这种没有 AI 问答段的）文字都写在那里，再开一个会先把前一个当「取消」关掉。页面只留这个确认框、发第二条之前的核对（视频页核对还是不是同一个视频，侧边栏核对对话有没有换）和显示回来的 `text`。视频页开着这个视频时，侧边栏用视频页的 `popup-refresh` 拿到它的笔记，作为 `page` 一起发，确认框也在侧边栏里。例外：视频页（`content.js` 的 `confirmOverwriteNote`）是 B站 页面上的内容脚本，用不了扩展页面的 dialog，自己画一份，文字和它一字不差，`download.selftest.js` 核对。
- 存储键名只写一份：不止一个文件用到的 `chrome.storage.local` 键名都在 `extension/limits.js` 的 `MdgLimits.KEYS` 里，运行时拼出来的键（`triage_analysis_<bvid>` 等）在那里有前缀和函数。键名的值不能改，改了用户的数据就找不到了。唯一一次改名是 3.6 把上游留下的前缀换成 `mdg_`：后台在更新和浏览器启动时用 `MdgLimits.migrateRenamedKeys` 把 local 和 session 里的旧键搬到新名字（新名字已有数据就不覆盖，写失败就留着旧键下次再搬），扩展页面的 `localStorage` 由侧边栏和分拣台在第一次读之前用 `migrateRenamedLocalStorage` 搬。`limits.selftest.js` 核对这些值，并在别的文件把它们写成字符串、`x.键名` 或 `{ 键名: … }` 时报错（selftest 和 dev 下的 mock 除外）。例外：`badges.js` 不加载 `limits.js`，自己照抄读到的五个名字，selftest 核对它们还在 KEYS 里；只有一个文件用的键留在那个文件（分拣台的 `K`）。关注的 `follow_*` 也还没进 KEYS：它们主要在 `follow-bg.js` 和 `follow.js` 里当属性名用（约 200 处），以后拆这两个文件时再收。
- 读一个视频（字幕、评论、分拣台的附加内容）有三处：视频页（`content.js`）、侧边栏接着问 AI（`background.js` 的 `resolveAiSidepanelContext`）和分拣台的细看 / 笔记（`triage-bg.js` 的 `triageAnalyze` / `triageBuildNote`）。它们共用这些，不各写一份：
  - 字幕时长检查只有 `MdgSites.validateSubtitleByDuration`。对不上的字幕照样用，配视频页那句「字幕时间轴到 X，视频长 Y，字幕时间可能对不上。」（`MdgNote.subtitleMismatchWarning`），只是不进字幕缓存；没有时长就不查。
  - 字幕这一步只有一份：`MdgSites.loadSubtitle`，三处都用它，怎么挑轨、怎么抓、怎么查、什么算失败什么算限流都在这里。读字幕轨列表，按 `io.subtitleLang` 排序，`prefer`（上次选的那条）放第一；`MdgSites.loadFirstTrack` 按顺序试，第一条和视频时长对得上的就用（进字幕缓存）。都对不上时再读一次列表、再试一遍（字幕文件为空时第二次不带 PO token）；还不行，YouTube 试视频页的文字稿；最后用第一条对不上的，带回 `mismatch`。限流（`THROTTLED` 或 HTTP 429）立即停下不再试别的轨，手里有对不上的就用它，没有就抛出，调用方等一会再试。其他失败（断网、超时、链接过期、字幕文件为空）不报错，带回 `error` 和 `failure`（去掉句号的原因），三处都写「字幕抓取失败：原因」。`step(promise)` 包住每一次等待，视频页靠它在换了视频后停下（`runStep`，作废的读取抛 `STALE_RUN`）；`io.fresh` 让视频页的读取不读缓存。
  - 视频页只多一层自己的抓取（`pageSubtitleSite`）：字幕列表重试 3 次，B站 回空列表时 1.5 秒后再问一次（后台不做：分拣台批量里每个没字幕的视频都会多一个请求和 1.5 秒，更容易碰到风控），后台请求被当成没登录时用页面的 cookie 再问；字幕文件 429 先等 3–5 秒重试一次，再 429 报「字幕接口限流（429）」。视频页把结果放进 `state`（`showSubtitle`），没有字幕时显示原因（`showNoSubtitleState`）。换字幕（`switchSubtitle`）只试选中的那一条（`loadFirstTrack`），读缓存。`content.selftest.js` 核对 `content.js` 不再自己写一份挑轨流程。
  - 分拣台的细看和笔记因此按简介和评论来：`triageAnalyze` 把原因记在 `subtitleFailure` 给卡片，`triageBuildNote` 照写笔记（`noteMeta.subtitleFailure`，和视频页笔记同一句开头），`subtitleWarning` 带上「字幕抓取失败：原因。」，视频记录页、侧边栏和「逐个视频笔记」都显示它。侧边栏接着问 AI（`resolveAiSidepanelContext`）也一样，把原因放进 `subtitleFailure`，和视频页传给侧边栏的字段同名，侧边栏照视频页那样写「字幕抓取失败」。
  - 热门评论条数是 `MdgSites.HOT_COMMENTS`（`fetchComments` 的默认值）。
  - 后台两处的笔记字段由 `MdgNote.noteMetaOf` 从 `sites.js` 的结果拼出（章节没有时从简介里解析，和视频页一样）。
  - 分拣台的附加内容（AI 总结只给 B站 P1、我的备注、分拣标签）由 `MdgNote.triageExtrasKeys` 列出要读的键、`MdgNote.triageExtras` 取出来；视频页、分拣台笔记和侧边栏的对话笔记都用它。视频记录页一次读出全部存储再按视频分组，不走它。
- 视频页的「当前视频」只有一个入口：`content.js` 的 `settledClip(force)`。弹窗、侧边栏、播放器上的 ✦ 和专注模式都经它读：先跑一次 `checkUrlChange`，让状态跟上标签页的地址（URL 轮询每 1.2 秒一次，中间不会拿到上一个视频，也不会再起一次读取）；有在跑的读取就等它，没有时只在 `force`（「刷新」）或还没读过时才起一个；被换视频作废的读取不算数（`checkUrlChange` 同时清掉 `refreshPromise`），等接替它的那次，或给现在的视频起一次；最后给现在这个视频的结果或它的失败。作废的读取晚到的失败（超时、限流、字幕失败）直接丢掉，不碰新视频的状态（`runRefreshClip` 的 catch 先比 `runId`）。
  - 页面和后台之间只有一条上下文消息：`sidepanel-get-context { refresh }`，内容脚本用 `clipContext` 回完整的上下文，热门评论也在里面（有就用 `state.hotComments`，没有就在这次读取里抓；抓的时候换了视频就重来，不会配上别的视频的评论）。后台 `getAiSidepanelState` 只发这一条，`ok: false` 就把 `error` 抛给侧边栏。弹窗用 `popup-refresh { force }`，也走 `settledClip`。打开弹窗、侧边栏跟着标签页时都不带 force，只有「刷新」带。
  - 分拣台的内置播放框也走这个入口。它的 ✦ 和专注模式的 AI 总结经后台交给侧边栏时，后台把 `sender.frameId` 和视频一起放进请求；侧边栏照常按视频打开它的对话（有存过的就打开最近那段），读这段对话的上下文时先问那个框：`ai-sidepanel-get-state { tabId, frameId, videoId }`，后台把 `sidepanel-get-context` 只发给那个框，所以框里选的字幕就是 AI 读的字幕；每次发问前再问一次。框关了，或自动连播换成了别的视频（内容脚本见 `videoId` 对不上就不回），就和关掉的视频页一样，由后台按视频去读（`resolveAiSidepanelContext`），侧边栏也不再问这个框。不用 `webNavigation` 权限。
  - 换字幕只有 `switchSubtitle`（弹窗和专注模式的下拉框）：字幕地址不在当前 `state.subtitles` 里就回「视频已切换，请刷新」；时长对不上的字幕照样用，带上提示。
- 侧边栏的对话和它的上下文只在 `extension/sidepanel-state.js`（`SidepanelState`）里：显示哪段对话、它绑定哪个视频、跟随播放（`decideFollow`）、AI 还在回答时离开（回答跟着原对话走，只有删除才丢掉）、输入框草稿属于对话（换对话就清空）、AI 总结什么时候填进输入框（跟随到空对话后、上下文到了才填，每段对话一次）、占位上下文都带 `pending`、对话自己的上下文和标签页是同一个视频就用标签页的，否则去读。它是纯的：不碰 `chrome.*` 和 DOM。显示的上下文不存，按对话推出来；换对话只有 `setConv` 一处，换了就加 `epoch`，晚到的读取按 `epoch` 作废。`sidepanel.js` 只是外壳：读标签页、存储、回答流（port）、计时器、Obsidian、备注、平台和快捷追问、弹层和画界面；它把发生的事 `dispatch` 进去，照返回的 effects 做（断开回答流、存对话、清草稿、填 AI 总结、读对话的上下文、设上一个视频……），画界面时对话和上下文只读 `view()`。规则的测试在 `sidepanel-state.selftest.js`（只用事件，不碰 DOM）；`sidepanel.selftest.js` 测外壳，并查 `sidepanel.js` 没有再声明这些状态。
- 发给 AI 的视频上下文只有一个写法：`note.js` 的 `MdgNote.buildAiContext`（视频页 `content.js` 和后台 `resolveAiSidepanelContext` 共用）。它就是笔记（`buildMarkdown`）去掉热门评论和播放器嵌入；嵌入只给 Obsidian，写入和下载的笔记照常带着。
- 收藏夹的纯函数放在 `extension/triage/triage-core.js`（`TriageCore`），`triage.js` 只留页面部分（DOM、存储、状态、计时）。现在里面是存储数据的形状（已出分拣范围的 `updateRemoved` / `moveToRemoved`、所有收藏夹的 `mergeFolderItems`、缓存列表的 `mergeHead` / `idsChanged` / `keepInvalidInfo` 等）和导出用的 Markdown 链接、zip 打包（`zipStored`）。放进去的函数只按参数算，不碰 DOM、`chrome.*`、`S` / `el` / `K` 和计时器；要改签名才算得上纯的留在 `triage.js`。`triage.html` 在 `triage.js` 之前加载它，`triage.selftest.js` 照 `triage.html` 的脚本清单加载（只跳过它自己替身的 `tag-dialogs.js`），并核对每个读 `TriageCore` 的页面先加载它。后台不用它。
- 撤销步骤只有一个形状 `{ kind, ask, blocked?, undo }`（`triage.js` 的 `pushUndo` 上面写着）：`undo()` 撤掉自己、返回提示，`ask` 是改了多个视频时先问的那句，`blocked()` 说为什么现在不能撤。收藏夹本地的那几种（保留、标签、AI 打标签、待播）用 `pageStep` 建，B站 写用 `favStep`，关注的 kind 是 `"mode"`、放在自己的栈里。U 只走一条路：问、弹出、`undo()`。加一种撤销只改推入的地方。
- 改 B站 的批量写在 `runs.js` 上面一层：`extension/triage/writes.js`（`MdgWrites.create`）只管写的规则，每个 adapter 一条自己的跑道（lane），各自的撤销栈，互不挡：收藏夹（`triage.js` 的 `fav`，键是 bvid，lane `fav`）和关注（`follow.js` 的 `relationRun`，键是 mid，lane `follow-write`）。两边胶囊上的「停止」都是 `W.stop()`，按下后变成「停止中」，灰掉的原因只有 `TriageUi.WRITE_STOPPING` 一份。
- 收藏夹改 B站 的写操作只有一条路：`triage.js` 的 `fav`（`unfav` 单个取消收藏、`unfavMany` 批量取消收藏、`transfer` 移动 / 复制 / 收藏到、`refav` 单个重新收藏、`refavBatch` 这批全部重新收藏、`state()` 给渲染和读取用），请求由 `writes.js` 发。`writes.js` 不碰 `S` / `el` / DOM，也不认识收藏夹：批量按块发（循环、间隔、限流重发同一块、停在失败的那块都是 `runs.js` 的）、哪些视频在等写（`pending`）、哪些收藏夹刚写过不能读（`writing`：批量在写它，或 3 秒内写过，单个写遇到限流的那次也算）。块怎么切也只在 `fav` 里一处（`chunkSize` / `chunkGap`：稍后再看和从已出分拣范围收藏到每次一个、间隔 300 ms，别的 20 个、间隔 1 秒）；后台 `triage-bg.js` 照样能收一组，因为 B站 稍后再看的接口本来就一次一个。撤销这些写的步骤自己带 `undo()`、`ask` 和 `blocked()`（批量在跑时不能撤）。`writes.selftest.js` 在 node 里测写的规则，`triage.selftest.js` 经 `fav.*`、U 和画出来的按钮测页面，`follow.selftest.js` 测 `relationRun`。
