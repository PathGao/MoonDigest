# MoonDigest 工程约定

这里记的是代码怎么组织、哪些东西只写一份。界面和交互的规则看 [DESIGN.md](DESIGN.md)。

B站 页面上的颜色是 `tokens.css` 的第三份拷贝：`content.css` 里的 `--boc-*`（`content-tokens.selftest.js` 会核对）和 `badges.css` 里直接写的色值（也由 `content-tokens.selftest.js` 核对，新写死的色值要加进它的 `BADGE_TOKENS` 表）。改 token 时，在同一个 PR 里把这两处一起改。

## 代码怎么共用

- 两种模式都画的东西，只在 `extension/triage/shared.js`（`TriageUi`）里写一份：标题行、排序、搜索框、筛选片、第 3/4 行的行名（`labeledRow`）、「AI 刚打的」片（`aiRecentChip`）、选中栏（`selbar`）、移动 / 复制弹窗（`askTransfer`：收藏夹传收藏夹，关注传分组）、左栏项（`sideItem`）、刷新和导出按钮、进度胶囊、空状态和里面的刷新（`refreshEmpty`）、头部随滚动收起（`headroom`）、列表为空的原因（`noMatch`）、撤销前的确认（`undoAsk`）、设置行（`fillSetRows`，包括「AI 打标签每批数量」）、格式化函数、AI 建议的合并（标签名清洗和标签颜色在 `extension/tag-core.js`）。「收藏夹设置」和「关注设置」两个弹窗的结构都写在 `triage.html` 里。发现两边各写了一份，就合并进去。
- 打标签面板只有一个：`extension/triage/tag-picker.js`。例外：B站 页面上的「+」标签面板（`badges.js`）在封闭的 shadow DOM 里，暂时用不了 tag-picker.js，标签的纯函数（颜色、标签名清洗、新标签 id、下一个颜色）放在 `extension/tag-core.js`（`BocTagCore`）里，`badges.js`、`shared.js`、`follow.js` 和 `triage.js` 都用它，manifest 和 `triage.html` 都在它们之前加载。`tag-core.selftest.js` 会查别处有没有再写一份。面板本身以后再迁到 tag-picker.js。「标签管理」和「✦ AI 打标签」弹窗也各只有一个：`extension/triage/tag-dialogs.js`；关注的「分组管理」也用「标签管理」这个弹窗，adapter 换掉标题、文字和每行的样子。模式打开它们时只传一个 adapter，里面是单位（视频 / UP 主）、上限和数据，文字、布局和确认页的计数（改动数、按标签汇总、「用在 N 个」）都在弹窗里。
- 所有输入框和快捷键都要走 `extension/typing.js`（`BocTyping`）：
  - 回车和 Esc 的处理函数，开头先写 `if (BocTyping.composing(e)) return;`。
  - 全局快捷键，开头写 `if (composing(e) || typingIn(e)) return;`。
  - 实时过滤的输入框用 `bindLive`。列表的搜索框用 `TriageUi.bindSearch`：Esc 清空，空框再按 Esc 移出焦点。
  - 这样以后新加的输入框，用输入法打字也不会出问题。
- 键盘只有一个全局处理函数，在 `triage.js` 的 `onKey` 里。内置播放框里按的 T / Esc 也只有一个 message 监听，同在 `triage.js`。关注模式用 `MoonTriage.setModeKeys` 注册自己的按键，两处都先问它。
- 内置播放框的 × 不放在 `#viewer` 里，而是紧跟在它后面的同一个格子（grid-area `viewer`）里，因为 `#viewer` 要 `overflow: hidden` 裁出圆角；`#viewer[hidden]` 时 CSS 把它一起藏起来。
- B站 页面上画什么只写一份：`badges.js` 的 `surfaceOf` 认出是哪种页面（首页和搜索、收藏夹、稍后再看和历史、动态、UP 空间、视频页、分拣台内置播放框），`bili-surfaces.js` 的 `SURFACES` 写每种页面显示哪些东西（设置页的表格也读它），顶栏弹窗按元素认（`.bew-popover`、`.v-popover`）。标签放得下多少只有一个函数：`fitCount` 算个数，`fitBoxes` 量宽度、藏掉放不下的、写「+N」，`ResizeObserver` 在容器变宽变窄时重量。观看进度的默认值、设置怎么读（`seenConfig`）和封面上的字（「✓ 看完了」「✓ 看到 N%」「看到 N%」，`seenWords`）也只写在 `bili-surfaces.js`，B站 页面、分拣台和设置页的示例都用它（`triage.html` 和 `options.html` 也加载它）；这三个默认值和 `settings.js` 的 `DEFAULTS` 各一份，`settings.selftest.js` 核对一致。算百分比的函数分两处：后台 `triage-bg.js` 的 `seenPercent` 算历史记录，分拣台 `triage.js` 的 `seenPercentOf` 先看历史、再看稍后再看自带的进度。
- 内置播放框下的标签行只有一种写法：`TriageUi.viewerLine`，行名用第 3/4 行的 `labeledRow`。收藏夹的「视频标签」行在 `triage.js`，「UP 标签」行在 `follow.js`，收藏夹每次画完自己那行就通过 `MoonTriage.setViewerHook` 让关注重画 UP 那行；B站 自动连播换了视频时（`triage.js` 的 `showViewing`），关注也在这个 hook 里把 `F.viewing` / `F.viewingMid` 换成新视频。
- 后台（`background.js` 的 service worker）也加载 `tag-core.js` 和 `shared.js`，日期、时长、标签名清洗直接用 `TriageUi`，不在 `triage-bg.js` 里另写。加载顺序以 `background.js` 的 `importScripts` 为准，后台的 selftest 照它读；侧边栏、视频记录页和视频页的 selftest 同样照 `sidepanel.html`、`history/history.html` 和 manifest 里 `content.js` 那一项读，不手写脚本清单。
- 「✦ AI 打标签」的后台只有一份：`triage-bg.js` 的 `triageAiCommand`（指令检查、新建上限 0–50、解析）。关注只把 UP 主整理成条目，带上自己的 unit 调它。
- 分拣台的限流等待只有一个：`triage.js` 的 `waitOut`（`MoonTriage.waitOut`），倒计时只存在 `S.waits`，按任务名一格，`tick()` 每秒重画；关注的任务名以 `follow-` 开头，不占收藏夹胶囊。AI 的超时和限流怎么数只有 `aiNext`，粗看、细看、AI 打标签共用。关注等 B站限流的 90 秒只有 `TriageUi.BILI_HOLD_MS`。后台的队列暂停（`follow_jobs.hold`、`follow_hold`）和观看进度的 30 分钟来自后台存储，不走它。
- 后台的 B站 GET 只走 `triage-bg.js` 的 `triageBiliGetJson`（带 B站 的 referrer、不缓存），30 秒没回应算断网（「网络断了」）。细看（`triageAnalyze`）和生成笔记（`triageBuildNote`）经 `TRIAGE_BILI_IO` 走它，另把风控码和「播放器接口回了却没有字幕对象」算成限流；侧边栏接着问 AI 的上下文（`resolveAiSidepanelContext`）也走它。`background.js` 的 `fetchJsonForAi` 只剩视频页的 `fetch-json` 代理。收藏夹每次只试一次，限流由页面退避；关注传入自己的队列（间隔、断网重试、风控整队暂停）。写操作 `triageBiliPost` 也有这 30 秒超时，但只发一次、从不自动重试；超时报「不确定 B站 是否已改」，调用方按失败处理，不改计数、不记撤销。风控码统一用 `BILI_RISK_CODES`，WBI 签名用 `sites.js`。
- 页面怎么显示一个错误只写一份：`extension/errors.js`（`BocErrors`）。后台负责分类（`triage-bg.js` 的 `triageAiHttpError`、`background.js` 的 `obsidianFailure`），回 `{ ok: false, error, code }`；页面用 `BocErrors.action(code)` 决定给「去设置」还是「去登录」（Obsidian 没配置或 Key 不对是 `OBSIDIAN`，给「去设置」；没打开是 `OBSIDIAN_DOWN`，不给），`BocErrors.text` / `fromResp` 读出要显示的话（B站 的 62004 换成「视频审核中，过后再试」），`grantOrigin` 认出「未授权访问 …」并给出授权按钮的请求，`reloaded` 认出扩展更新后内容脚本失效。HTML 转义也只有这里一份：`BocErrors.escapeHtml` 转 `& < > " '` 五个字符，页面、视频页和分拣台（`TriageUi.esc` 就是它）拼 HTML 都用它，`errors.selftest.js` 查别处有没有再写一份；`badges.js` 用 `textContent` 建 DOM，不需要它。Obsidian 的三句话和「扩展刚刚更新，请刷新网页」只写在 `BocErrors.TEXT` 里，后台也读它。内容脚本、后台和每个用到它的页面都在用它的脚本之前加载 `errors.js`（`load-order.selftest.js` 核对），`errors.selftest.js` 查别处有没有再写一份这些话。例外：`badges.js` 不加载它，自己照抄一份「扩展刚刚更新，请刷新网页」，selftest 核对两份一字不差。
- 设置的默认值和整理函数只写一份：`extension/settings.js`（`BocSettings`）。`DEFAULTS`（sync）和 `LOCAL_DEFAULTS`（Obsidian 的 Key）是唯一一份默认值，默认的 AI 提示词也只写在这里；后台 `normalizeSyncSettings` 用它存设置，页面和内容脚本只在 get-settings 失败时拿 `DEFAULTS` 兜底。几个页面都要的整理函数（API Key、下载格式、AI 总结要求、快捷追问和它的 12 条上限、自定属性、正文附加段落、阅读视图）也在这里，字符串一律按 `String(v ?? "")` 处理，数字保留。设置页自己的表单检查留在 `options.js`。`note.js` 也读它，所以凡是加载 `note.js` 的地方都先加载 `settings.js`；加载顺序由 `load-order.selftest.js` 核对；`settings.selftest.js` 查别处有没有再写一份默认提示词或这些函数。
- AI 判断的三类（值得留 / 可清理 / 拿不准）和怎么判只写一份：`extension/tag-core.js` 的 `VERDICTS` 和 `verdictOf`（细看优先于粗看，已失效一律可清理）。分拣台（`triage.js`）、B站 页面（`badges.js`）、后台（`triage-bg.js` 认模型的回答）和笔记里的「AI 判断：…」（`note.js`）都读它，所以凡是加载 `note.js` 的地方也先加载 `tag-core.js`，加载顺序由 `load-order.selftest.js` 核对，`tag-core.selftest.js` 查别处有没有再写一份。B站 页面只在收藏夹页知道哪些视频已失效（读这个收藏夹的 `triage_snapshot_<fid>`）；别的页面不读，所有收藏夹的快照太大。
- 「该笔记已存在」确认框在扩展页面上只有一个：`extension/download.js` 的 `BocOverwriteDialog.choose`（原生 `<dialog>`，样式在 `tokens.css`），侧边栏和视频记录页都用它；三种情况（有 AI 问答可更新、没有 AI 问答可更新、对话笔记这种没有 AI 问答段的）文字都写在那里，再开一个会先把前一个当「取消」关掉。侧边栏和视频记录页写后台生成的 B站 视频笔记（问覆盖 → 写笔记 → 写 AI 问答段）都走 `BocOverwriteDialog.writeBuiltNote`。例外：视频页（`content.js` 的 `confirmOverwriteNote`）是 B站 页面上的内容脚本，用不了扩展页面的 dialog，自己画一份，文字和它一字不差，`download.selftest.js` 核对。
- 存储键名只写一份：不止一个文件用到的 `chrome.storage.local` 键名都在 `extension/limits.js` 的 `BocLimits.KEYS` 里，运行时拼出来的键（`triage_analysis_<bvid>` 等）在那里有前缀和函数。键名的值不能改，改了用户的数据就找不到了。`limits.selftest.js` 核对这些值，并在别的文件把它们写成字符串、`x.键名` 或 `{ 键名: … }` 时报错（selftest 和 dev 下的 mock 除外）。例外：`badges.js` 不加载 `limits.js`，自己照抄读到的五个名字，selftest 核对它们还在 KEYS 里；只有一个文件用的键留在那个文件（分拣台的 `K`）。关注的 `follow_*` 也还没进 KEYS：它们主要在 `follow-bg.js` 和 `follow.js` 里当属性名用（约 200 处），以后拆这两个文件时再收。
- 发给 AI 的视频上下文只有一个写法：`note.js` 的 `BocNote.buildAiContext`（视频页 `content.js` 和后台 `resolveAiSidepanelContext` 共用）。它就是笔记（`buildMarkdown`）去掉热门评论和播放器嵌入；嵌入只给 Obsidian，写入和下载的笔记照常带着。
- 收藏夹的纯函数放在 `extension/triage/triage-core.js`（`TriageCore`），`triage.js` 只留页面部分（DOM、存储、状态、计时）。现在里面是存储数据的形状（已出分拣范围的 `updateRemoved` / `moveToRemoved`、所有收藏夹的 `mergeFolderItems`、缓存列表的 `mergeHead` / `idsChanged` / `keepInvalidInfo` 等）和导出用的 Markdown 链接、zip 打包（`zipStored`）。放进去的函数只按参数算，不碰 DOM、`chrome.*`、`S` / `el` / `K` 和计时器；要改签名才算得上纯的留在 `triage.js`。`triage.html` 在 `triage.js` 之前加载它，`triage.selftest.js` 照 `triage.html` 的脚本清单加载（只跳过它自己替身的 `tag-dialogs.js`），并核对每个读 `TriageCore` 的页面先加载它。后台不用它。
- 收藏夹改 B站 的写操作只有一条路：`triage.js` 的 `fav`（`unfav` 单个取消收藏、`unfavMany` 批量取消收藏、`transfer` 移动 / 复制 / 收藏到、`refav` 单个重新收藏、`refavBatch` 这批全部重新收藏、`state()` 给渲染和读取用），请求由 `extension/triage/writes.js`（`BocWrites.create`）发。`writes.js` 只管写的规则，不碰 `S` / `el` / DOM，也不认识收藏夹：批量同一时间只跑一个（第二个被拒并报出在跑的那个名字）、按块发并在块之间留间隔、遇到限流等完再重发同一块、别的失败停在那一块、哪些视频在等写（`pending`）、哪些收藏夹刚写过不能读（`writing`：批量在写它，或 3 秒内写过，限流的那次也算）。块怎么切也只在 `fav` 里一处（`chunkSize` / `chunkGap`：稍后再看和从已出分拣范围收藏到每次一个、间隔 300 ms，别的 20 个、间隔 1 秒）；后台 `triage-bg.js` 照样能收一组，因为 B站 稍后再看的接口本来就一次一个。撤销这些写的步骤自己带 `undo()`、`ask` 和 `blocked()`（批量在跑时不能撤），和关注的步骤是同一个形状，`undo()` 只有一个分支处理它们。`writes.selftest.js` 在 node 里测引擎，`triage.selftest.js` 经 `fav.*`、U 和画出来的按钮测页面。关注的写（`follow.js` 的 `relationRun`）以后也会接到 `writes.js` 上。
